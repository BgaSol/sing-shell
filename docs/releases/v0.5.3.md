# Sing Shell v0.5.3

macOS TUN 改为连接时通过系统管理员授权启动短期 worker，断开后退出。保留同安装、同构建运行代码的双向身份校验与有界握手，不再依赖跨版本 SMAppService 网络服务登记。旧登记仅在确认闲置且属于本应用时撤销。

实机追查确认：ad-hoc 签名更新后，旧登记的启动约束拒绝当前构建，随后失效为 EX_CONFIG；重新允许、刷新应用登记和注销后重新登记均不能可靠恢复。同一程序使用全新登记可启动，但逐版本换服务名不是长期方案。维护者选择按需系统授权，无需 Apple Developer ID 证书。

## 验收状态

固定源码 `b3899438f85563f126fec7410f5fa28c370ed740` 的[五原生 Check](https://github.com/BgaSol/sing-shell/actions/runs/45812180027)、[五原生 TUN 集成](https://github.com/BgaSol/sing-shell/actions/runs/45812193563)及[签名打包与实际安装升级](https://github.com/BgaSol/sing-shell/actions/runs/45812184324)均通过。ARM64 全部使用原生运行器。

维护者的 macOS 26.7.3 Apple Silicon 实机使用最终发行原包，以普通用户从桌面应用会话完成管理员授权，验证双方运行身份、官方核心、真实 TUN、Shadowsocks 加密 IPv4/IPv6 TCP/UDP 往返、停止后接口及 worker/授权启动器退出。仅两个专用测试地址经过测试节点，其他流量直连；旧系统作业及临时对照作业均已撤销。实机不注入崩溃，可丢弃运行器覆盖异常退出清理。

Windows ARM64 首次实际包验收在末尾 CurrentUser 重新安装后的卸载保护返回 2，前序安装、TUN、设置保留及升级已通过；同源码、原包和断言在新原生运行器重跑通过。保留首次失败，尚不能确定归因于环境。本地 103 项 Rust 测试通过，4 项需外部核心的默认测试明确跳过；类型/格式、13 项脚本、NSIS 构建与 smoke 通过，本地脚本一次 UDP 端口 EACCES 后重跑通过。

发行草稿 16 个附件的大小和 SHA-256 与原包一致，更新清单五平台 URL、签名、大小和摘要一致。完整记录见[包验证证据](v0.5.3-verification.json)与[网络验证证据](v0.5.3-network-verification.json)。

Mac 连接时可能要求管理员密码，断开即退出，不再依赖“登录项与扩展”的网络授权；应用不接收或保存密码。设置 schema 保持 4，节点、分流及外部核心选择保留。macOS 仍为 ad-hoc 签名、未公证；实际托盘视觉、注销/登录、休眠及物理切网本次未验收。
