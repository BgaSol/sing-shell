# Sing Shell v0.5.1

修复带 `encryption=none` 的 VLESS 分享链接导入，保留 TLS、WebSocket Host、路径与独立 SNI；缺省与显式 none 按相同节点去重。整理共享链接解析，严格检查编码、重复与未知参数，拒绝冲突的 TLS 不安全开关。

修复新预览失败后旧票据仍可提交；文件读取和非法 UTF-8 失败会清除旧预览，错误行号保留原始空行。设置 schema、已有节点和受限网络 worker 协议保持兼容。

## 验收与发行来源

本地 Windows x86_64 的类型/格式检查、11 项工程脚本检查和 Rust 测试通过；默认 Rust 测试 92 项通过、4 项真实核心测试明确跳过。另使用官方 sing-box 1.14.4 实际执行包含 ignored 项的 8 项 profile 集成，全部通过，覆盖完整 VLESS + TLS + WebSocket 分享链接生成配置，以及受控加密出口分流。配置通过不代表用户节点实际握手或转发已验证。

正式发布前补齐固定源码、五原生 Check、签名包与独立实际包验收结果，并记录原始摘要及跳过范围。本版包验证增加 v0.5.0 → 本版的签名升级与已有 VLESS 节点保留。

## 已知边界

- WebSocket Host 不自动作为 TLS SNI；真实服务器的证书名称要求仍应由链接的 `sni` 表达。
- 非法 URL 编码、非法 UTF-8 文件和冲突的 TLS 别名现在明确拒绝，已有持久化节点不会批量重写。
- Windows 无发行商代码签名；macOS 使用 ad-hoc 签名，未公证。updater 使用独立正式签名。
- UAC/polkit 交互、macOS 用户允许后的 launchd 激活、实际注销登录、物理切网及其他 VPN 共存没有由本次节点解析回归代替验证。
