# Sing Shell v0.5.2

修复 macOS TUN 授权连接过早检查 launchd 身份的问题：由 helper 接管并就绪后验证同安装、同构建的运行程序，再双向确认控制会话。授权等待、激活、身份及协议阶段分别显示；旧 helper 不通过协议降级混用。

收拢网络会话及 worker 所有权，停止/退出超时保留原任务供重试，查询不触发清理；修复纯节点恢复误要求原始配置路径。托盘改用可识别的贝壳及状态标记，macOS 更新图像时保留单色模板属性。Windows 安装器支持当前用户及所有用户安装，更新保留原范围。

## 验收状态

固定源码 `1b76707a0a209796fbb4f50f06bc0ab081987d71` 的[五原生 Check](https://github.com/BgaSol/sing-shell/actions/runs/45793402798)、[五原生网络集成](https://github.com/BgaSol/sing-shell/actions/runs/45793387050)和[签名打包及独立实际包验收](https://github.com/BgaSol/sing-shell/actions/runs/45793395495)均已通过。macOS 原生回归确认延迟 accept 前后身份变化、生产 Rust verifier 的真实 launchd 激活，以及同路径替换程序不能让旧进程取得新构建身份。

本地 Windows x64 类型/格式检查、13 项脚本、默认 Rust 101 项通过；4 项需官方核心的用例在默认运行中明确跳过，随后使用已核对摘要的官方 sing-box 1.14.4 实际执行 real_core 2 项及 profile 8 项（包含 ignored），全部通过。NSIS 构建和隔离启动、收起、退出通过。单元测试明确禁止调用真实提权入口。

五个平台实际包均验证官方核心、加密 IPv4/IPv6 TCP/UDP、异常清理、安装/退出及生产更新交接；v0.2.0 / v0.3.0 / v0.4.0 / v0.5.0 / v0.5.1 → 本版保留设置、节点及外部核心选择，本版 → 隔离 0.5.3 候选核对实际版本和恢复。macOS 首次实际包验收遇到既有加密回环分流测试提前 EOF；同源码、同原包重跑通过，未放宽断言或重建包，失败及复跑记录保留在证据中。

[v0.5.2](https://github.com/BgaSol/sing-shell/releases/tag/v0.5.2) 的 16 个附件已逐一核对原包大小、SHA-256，更新清单五平台 URL/签名/大小/摘要与原包一致。完整摘要及测试范围见[包验证证据](v0.5.2-verification.json)和[网络验证证据](v0.5.2-network-verification.json)。

已正式发布并设为 [Latest](https://github.com/BgaSol/sing-shell/releases/latest)，实现经 [PR #3](https://github.com/BgaSol/sing-shell/pull/3) 合入主分支；发布继续使用已验收的原包，未重新构建或覆盖附件。

macOS 普通用户在系统设置允许后的 SMAppService 激活及真实 TUN、实际托盘视觉验收本次未执行，不能用 root worker 或隔离 launchd 任务替代。维护者明确要求在上述自动验证通过后直接发布，保留这些未覆盖范围，不将其计作通过。

设置保持 schema 4；已有节点、分流、恢复偏好和外部核心选择保留。macOS TUN 要求完整 app 安装到 Applications，仍使用 ad-hoc 签名、未公证；Windows 无发行商签名，updater 使用独立正式签名。
