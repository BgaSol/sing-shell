# 核心与配置

## 首次使用和核心来源

新安装默认由应用管理官方 sing-box。打开应用即恢复本地材料，没有核心时自动下载本机系统与架构的正式稳定版。准备完成后显示版本和就绪状态，不自动启动代理。失败可以在首页重试，也可展开高级选项使用本机核心。

新安装使用节点模式，选择单个节点生成 TUN 配置，域名/IP/站点分流见对应功能合同。受控 TUN 仅使用应用管理的官方核心，当前能力档为 1.14.4–1.14.x；未经验证的主次版本不会以管理员权限执行。1.14.4 的官方发行元数据随应用固定，避免首次连接依赖匿名 API 限额。首次授权需准备一份独立受保护核心，后续核验通过可离线复用。原始配置模式仍可使用本机核心。

使用本机核心会执行 `sing-box version` 核对正式版本；该外部程序由用户管理，应用不覆盖、移动或删除它。外部路径失效会报错，不自动改为托管。主动切回应用管理时先验证可用本地版本，或准备官方程序，在核心和配置可用前保留外部选择。

旧版的外部选择保持原样，不因应用升级被接管。核心自动更新、安全采用、恢复和取消见[软件更新](updates.md)。

## 配置导入

配置继续引用原绝对路径，不复制、改写、删除或上传。运行工作目录始终是配置父目录，保留相对规则文件等资源路径。JSON/JSONC 语义由 sing-box 检查，壳不另写配置解析器。

有可用核心时执行 `sing-box check -c <路径>`，通过才替换有效配置；错误保留此前选择。核心尚未准备好时，可以先选择可读文件，显示“等待核心校验”，该路径单独保存。核心就绪后检查，通过再提升为有效配置；配置错误不导致重新下载核心。

每次启动都会重新校验文件。运行中不能改变核心来源或配置选择，修改原文件不会自动热加载。配置/规则检查可能依 sing-box 的行为读取远程资源；壳不自动修复或重写配置，不承诺任意用户配置都能离线通过检查。

## 启动、停止和一次回退

原始配置启动使用固定程序、配置与工作路径，不等待发行网络。受控 TUN 的首次授权核心及未缓存规则需联网准备，准备过程可取消。有旧版可用时后台下载不阻止启动；无核心时提示等待准备；一次恢复见[桌面与启动](desktop.md)。

进程创建后先观察存活 2 秒。原始配置据此确认运行，不保证远端可达。受控 TUN 还必须确认真实 PID、预期接口地址及 IPv4/IPv6 路由覆盖；局部路由或单个半区不算就绪，官方核心排除保留地址后拆分的网段按覆盖范围核对。macOS 还需确认临时系统 DNS 和独立物理上游，全部就绪才显示已连接；该状态不冒充节点远端连通性，也不依赖固定外网探测。后期异常不自动重启。

新采用的受管核心在首次启动校验、进程创建或观察期失败时，确认新进程和日志资源已结束，再校验上一版本及同一配置。可用则回退并尝试启动一次；旧版也失败就停止，保留两次原因。没有上一版本时直接显示失败。用户停止、取消、退出、来源切换和普通网络不通不触发回退运行。

停止先尝试有界优雅关闭（Unix SIGTERM；Windows 网络 worker 的 CTRL_BREAK），超时使用进程组/Job 强制终止。普通 Windows 原始配置仍由 Job 结束。启动中可停止。窗口收起继续运行，真正退出等待维护和网络收尾；清理失败保留真实状态，禁止安装或第二个连接。成功启动保存恢复依据；主动停止撤销，内部清理不抹掉意图。默认不恢复，每次启动至多尝试一次。

## TUN 授权与清理

GUI 保持普通用户权限。Windows 按需 UAC，Linux 按需 pkexec/polkit；macOS 通过系统管理员授权弹窗启动短期 worker，每次连接按需授权。worker 只接受闭合类型节点、分流及官方版本，不接受任意核心路径、配置路径或管理员命令。控制通道验证对等端身份和同一应用程序，消息/时限有界。

macOS 受控 TUN 要求完整应用安装到 `/Applications` 或 `~/Applications`，不从 DMG、临时目录或裸开发程序请求网络授权。系统只授权当前应用的固定 worker 入口，启动参数通过 AppleScript 的 `quoted form` 传递；节点、核心路径和任意命令均不进入授权脚本。连接时可能要求输入管理员密码，应用不接收、不保存密码。拒绝、取消或超时不会启动核心，之后可重新连接。

控制端创建独占、仅自身可访问的随机本地 socket 目录。双方核对内核审计身份、同安装位置及运行代码签名，再确认本次握手协议，之后才传节点。断开后等待真实 worker 及授权启动器退出。macOS 不依赖后台登录项、不自动恢复需要弹窗的 TUN，也不保留跨版本网络服务登记；原始配置模式不变。

升级时保留旧 plist 仅用于撤销旧 SMAppService 登记，绝不重新登记。撤销前核实固定作业归属、入口、PID 和活动数；运行中的旧 helper 必须先由旧实例断开，未知作业不会自动停用。旧 daemon 入口不再接受连接。历史 ad-hoc 构建的缓存启动约束失效不会被当作用户未允许，更不通过更换服务名或重复登记规避。

受保护核心位于 ProgramData/Sing Shell Network、/var/lib/sing-shell-network 或 /Library/Application Support/Sing Shell Network，由 worker 独立验证官方摘要。机器级租约禁止第二个 TUN 所有者。控制端消失或心跳超时会停止核心；worker 崩溃后在下次授权时核对受保护的 PID、启动身份和实际程序路径再清理，不能误杀复用 PID。

断开等待真实接口释放。失败显示需要清理，可重新授权执行清理，不重新连接旧节点。保存不热更新；应用前先校验候选，失败恢复上一成功连接一次，恢复过程中不嵌套核心回退。

内部应用更改可复用同一短期认证通道；用户断开和退出结束整个控制会话并等待按需 helper 退出。停止或退出超时仍保留原任务所有者，阻止第二套连接及更新交接，重试继续收尾同一任务。查询状态不发起清理；核心退出和控制端失联由 worker 自身处理。macOS 不保留网络服务或全局监听端点。

授权启动器自创建起就由控制会话持有，取消、认证失败及超时均进入同一退出等待，未知退出状态不当作已结束。worker 的启动任务交回资源后才由主循环发布运行／失败，迟到启动不能覆盖停止。启动失败、取消、断开及异常共用清理：释放本次 DNS、停止核心及日志、核对残留与接口、删除生成配置。原始失败和清理失败都保留；未完成清理继续阻止重入。

## 数据和日志

设置位于系统应用数据目录 `com.bgasol.singshell`。schema 4 分开保存核心、节点/分流、偏好和成功连接恢复依据；0/1/2/3 先备份原字节后迁移。损坏或未知结构保留原件、阻止覆盖和自动维护。同一数据目录只能有一个管理实例。回装旧应用需恢复相应备份，旧应用不能读取新 schema。

stdout、stderr 与壳消息附接收时间和来源。内存最多保留本次应用的 1,000 条记录，原始行达到 8 KiB 时拆分。关闭“跟随最新”可以阅读旧记录；退出即清空。核心自己的文件日志由 sing-box 配置控制。

版本/配置检查超时 15 秒会结束检查并报错；程序架构、权限、文件缺失及启动端口冲突均显示实际原因。日志可能含地址，分享前自行检查。

不提供订阅自动更新、节点测速、策略组、系统代理开关或崩溃重连。原始配置中的高级能力仍服从 sing-box 与系统权限；壳不将任意用户配置送入授权 worker，也不改写其非回环监听设置。
