# 核心与配置

## 首次使用和核心来源

新安装默认由应用管理官方 sing-box。打开应用即恢复本地材料，没有核心时自动下载本机系统与架构的正式稳定版。准备完成后显示版本和就绪状态，不自动启动代理。失败可以在设置的核心与更新页重试；本机核心用于原始配置。

新安装使用节点模式，选择单个节点生成 TUN 配置，域名/IP/站点分流见对应功能合同。受控 TUN 仅使用应用管理的官方核心，当前能力档为 1.14.4–1.14.x；未经验证的主次版本不会以管理员权限执行。受管更新采用 Sing Shell 验证发布的官方版本，可能晚于上游。普通维护先准备程序与项目签名材料；首次连接在系统授权后离线复核并安装受保护副本，不再查询核心发行 API 或重新下载核心。包内提供已批准的 1.14.4/1.14.5 材料，已选和上一版本的材料跟随来源记录保留。原始配置模式仍可使用本机核心。

使用本机核心会执行 `sing-box version` 核对正式版本；该外部程序由用户管理，应用不覆盖、移动或删除它。外部路径失效会报错，不自动改为托管。主动切回应用管理时先验证可用本地版本，或准备官方程序，在核心和配置可用前保留外部选择。

本代已选外部程序继续由用户维护，应用不覆盖它。旧代设置拒绝读取并保留原件，需显式初始化。核心自动更新、安全采用、恢复和取消见[软件更新](updates.md)。

显式初始化后在同一应用进程内重新恢复本地核心材料，不自动连接。受管目录已有程序、设置却没有安装记录时，按官方候选和已核验材料判断：相同字节复用并补齐选择；暂存程序损坏可从有效归档重新准备，不重复下载。缺少来源依据不能仅凭目录或版本输出恢复信任。

未登记的目标文件与候选不同时，自动维护暂停；明确重试只允许替换未被有效选择或外部来源占用的受管普通文件。有效当前/上一版本、链接、目录和外部程序不会被强制覆盖。设置备份与初始化失败不破坏原设置；初始化成功后的核心错误单独呈现，不自动恢复旧节点和凭据。

## 配置导入

配置继续引用原绝对路径，不复制、改写、删除或上传。运行工作目录始终是配置父目录，保留相对规则文件等资源路径。JSON/JSONC 语义由 sing-box 检查，壳不另写配置解析器。

有可用核心时执行 `sing-box check -c <路径>`，通过才替换有效配置；错误保留此前选择。核心尚未准备好时，可以先选择可读文件，显示“等待核心校验”，该路径单独保存。核心就绪后检查，通过再提升为有效配置；配置错误不导致重新下载核心。

每次启动都会重新校验文件。运行中不能改变核心来源或配置选择，修改原文件不会自动热加载。配置/规则检查可能依 sing-box 的行为读取远程资源；壳不自动修复或重写配置，不承诺任意用户配置都能离线通过检查。

## 启动、停止和一次回退

原始配置启动使用固定程序、配置与工作路径，不等待发行网络。受控 TUN 的核心下载及签名材料在普通维护阶段准备；授权安装核心不需要发行网络，未缓存规则仍可能需要联网，过程可取消。有旧版可用时后台下载不阻止启动；无核心时提示等待准备；一次恢复见[桌面与启动](desktop.md)。

进程创建后先观察存活 2 秒。原始配置据此确认运行，不保证远端可达。受控 TUN 还必须确认真实 PID、预期接口地址及 IPv4/IPv6 路由覆盖；局部路由或单个半区不算就绪，官方核心排除保留地址后拆分的网段按覆盖范围核对。显式绕过目标同时要求没有被本应用 TUN 路由接管，剩余范围仍完整覆盖；不能仅把排除当作忽略检查。macOS 还需确认临时系统 DNS 和独立物理上游，全部就绪才显示已连接；该状态不冒充节点远端连通性，也不依赖固定外网探测。后期异常不自动重启。

新采用的受管核心在首次启动校验、进程创建或观察期失败时，确认新进程和日志资源已结束，再校验上一版本及同一配置。可用则回退并尝试启动一次；旧版也失败就停止，保留两次原因。没有上一版本时直接显示失败。用户停止、取消、退出、来源切换和普通网络不通不触发回退运行。

停止先尝试有界优雅关闭（Unix SIGTERM；Windows 网络 worker 的 CTRL_BREAK），超时使用进程组/Job 强制终止。普通 Windows 原始配置仍由 Job 结束。启动中可停止。窗口收起继续运行，真正退出等待维护和网络收尾；清理失败保留真实状态，禁止安装或第二个连接。成功启动保存恢复依据；主动停止撤销，内部清理不抹掉意图。默认不恢复，每次启动至多尝试一次。

## TUN 授权与清理

GUI 保持普通用户权限。Windows 按需 UAC，Linux 按需 pkexec/polkit；macOS 通过系统管理员授权弹窗启动短期 worker，每次连接按需授权。worker 只接受闭合类型节点、分流及官方版本，不接受任意核心路径、配置路径或管理员命令。控制通道验证对等端身份和同一应用程序，消息/时限有界。

macOS 受控 TUN 要求完整应用安装到 `/Applications` 或 `~/Applications`，不从 DMG、临时目录或裸开发程序请求网络授权。系统只授权当前应用的固定 worker 入口，启动参数通过 AppleScript 的 `quoted form` 传递；节点、核心路径和任意命令均不进入授权脚本。连接时可能要求输入管理员密码，应用不接收、不保存密码。拒绝、取消或超时不会启动核心，之后可重新连接。

控制端创建独占、仅自身可访问的随机本地 socket 目录。双方核对内核审计身份、同安装位置及运行代码签名，再确认本次握手协议，之后才传节点。断开后等待真实 worker 及授权启动器退出。macOS 不依赖后台登录项、不自动恢复需要弹窗的 TUN，也不保留跨版本网络服务登记；原始配置模式不变。

升级时保留旧 plist 仅用于撤销旧 SMAppService 登记，绝不重新登记。撤销前核实固定作业归属、入口、PID 和活动数；运行中的旧 helper 必须先由旧实例断开，未知作业不会自动停用。旧 daemon 入口不再接受连接。历史 ad-hoc 构建的缓存启动约束失效不会被当作用户未允许，更不通过更换服务名或重复登记规避。

受保护核心位于 ProgramData/Sing Shell Network、/var/lib/sing-shell-network 或 /Library/Application Support/Sing Shell Network，由 worker 使用内置项目公钥独立验签并验证程序字节，项目签名表示已核对官方资产，不冒充上游原生签名。机器级租约禁止第二个 TUN 所有者。控制端消失或心跳超时会停止核心；worker 崩溃后在下次授权时核对受保护的 PID、启动身份和实际程序路径再清理，不能误杀复用 PID。

断开等待真实接口释放。失败显示需要清理，可重新授权执行清理，不重新连接旧节点。保存不热更新；应用前先校验候选，失败恢复上一成功连接一次，恢复过程中不嵌套核心回退。

内部应用更改可复用同一短期认证通道；用户断开和退出结束整个控制会话并等待按需 helper 退出。停止或退出超时仍保留原任务所有者，阻止第二套连接及更新交接，重试继续收尾同一任务。查询状态不发起清理；核心退出和控制端失联由 worker 自身处理。macOS 不保留网络服务或全局监听端点。

授权启动器自创建起就由控制会话持有，取消、认证失败及超时均进入同一退出等待，未知退出状态不当作已结束。worker 的启动任务交回资源后才由主循环发布运行／失败，迟到启动不能覆盖停止。启动失败、取消、断开及异常共用清理：释放本次 DNS、停止核心及日志、核对残留与接口、删除生成配置。原始失败和清理失败都保留；未完成清理继续阻止重入。

## 数据和日志

设置位于系统应用数据目录 `com.bgasol.singshell`。schema 5 分开保存核心、节点、分流、偏好和成功连接恢复依据；旧代结构保留原件，只有显式备份初始化才重置。损坏或未知结构保留原件、阻止覆盖和自动维护。同一数据目录只能有一个管理实例。回装旧应用需恢复相应备份，旧应用不能读取新 schema。

stdout、stderr 与壳消息附接收时间和来源。内存最多保留本次应用的 1,000 条记录，原始行达到 8 KiB 时拆分。关闭“跟随最新”可以阅读旧记录；退出即清空。核心自己的文件日志由 sing-box 配置控制。

版本/配置检查超时 15 秒会结束检查并报错；程序架构、权限、文件缺失及启动端口冲突均显示实际原因。日志可能含地址，分享前自行检查。

不提供订阅自动更新、节点测速、策略组、系统代理开关或崩溃重连。原始配置中的高级能力仍服从 sing-box 与系统权限；壳不将任意用户配置送入授权 worker，也不改写其非回环监听设置。

## Fake-IP 映射与受保护状态

连接输入统一冻结节点、有效分流、来源版本、核心和 IPv4 兼容选项。配置编译集中组装 DNS、真实解析、路由、映射缓存及可选活动接口；worker 不在编译后覆盖 JSON。

授权协议 6 在确认对等端身份后，从真实控制进程的 Unix UID / Windows SID 派生用户缓存目录，拒绝不认识绕过语义的旧 worker。机器级租约继续禁止第二个 TUN；映射按用户隔离，由官方核心保存在受保护 state/<用户摘要>/fakeip-v1/cache.db。临时配置仍按会话删除，映射跨正常重连和换节点保留，不把缓存路径或内容回传前端。

候选只 check，不启动或抢占当前缓存；旧进程真实退出后新核心才打开同一文件。准备失败保持旧连接，新启动失败最多恢复一次旧固定输入。断开/退出关闭核心、数据库和 helper，释放 TUN/DNS，保留本机映射文件。仅 store_fakeip 开启，不持久化历史真实 DNS 回答。

映射包含访问域名，属于本机敏感材料。核心强杀前未落盘的映射、缓存外部删除/损坏及地址池回绕不保证透明恢复；可能需重新解析或重启浏览器。壳不修复数据库、猜域名或偷偷切换解析后端。旧程序不保证读取新增字段，回装按已有备份约定处理。

## 绕过域名的连接准备

仅启用精确域名绕过时，授权 worker 使用同一已验签官方核心启动一个短期 DNS 实例：没有 TUN、节点凭据或 Fake-IP 缓存，仅有本机随机鉴权控制端点。核心负责系统上游、DNS 协议与 CNAME；壳校验响应状态、问题、地址族、大小及保护范围，不实现 DNS 转发器。域名绕过需要 with_clash_api 能力，缺少时明确失败；普通连接与字面 IP 绕过不依赖此能力。

Windows/macOS 使用官方 local transport；Linux 从默认网络接口读取 resolvectl DNS，不可用时读取 resolv.conf，排除回环和本应用隧道 DNS，由官方 UDP transport 绑定该接口查询。没有独立 DNS 时准备失败，保留旧连接，不静默换公共 DNS 或要求先停代理。多网卡和其他 VPN 的系统选择仍有边界，不提供网卡或 DNS 服务器选择界面。

固定解析结果仅由 worker 持有，与同一会话的 DNS 回答、排除路由和就绪预期共同编译。临时进程及 reader 真实退出后才切换旧 TUN；准备目录和进程分别登记在受保护的 preparing / preparation-process 记录。认证并取得机器级租约后核对旧残留身份，正常停止及异常统一清理，清理失败保留所有权供重试。

核心采用和离线配置检查使用独立的 check 编译入口，不解析绕过域名；只有完整解析的运行结果才能形成正式启动配置。应用内一次失败恢复复用旧实际结果；重新打开应用后的新连接重新解析，不把运行 IP 写入 lastConnection。
