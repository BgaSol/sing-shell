# 核心与配置

## 选择和导入

选择本机核心后，壳执行 `sing-box version` 并解析正式版本号。外部核心由用户管理，不由壳覆盖；也可通过[软件更新](updates.md)明确安装和采用应用管理的官方核心。

配置导入引用用户选择的原始文件，不复制、重写或删除它。执行 `sing-box check -c <绝对配置路径>` 通过后才保存选择；工作目录始终为该配置的父目录，保留相对规则文件等资源路径。配置可以使用该核心支持的 JSON / JSONC 格式，语义由 sing-box 检查。

导入失败时保留先前保存的位置。核心来源、配置路径和更新偏好保存在 Tauri 的应用数据目录 `com.bgasol.singshell` 下；具体根路径由操作系统决定。v0.1.0 设置迁移时保留备份，原核心路径作为外部来源保留。配置和日志不上传。

## 启动和停止

每次启动先重新校验当前文件，随后执行 `sing-box run -c <绝对配置路径>`。核心运行中不能更换核心或配置；启动按钮不会创建第二个运行实例。修改原文件后需停止并重新启动，运行中的配置不会自动热加载。

“核心运行中”只表示受管进程尚未退出，不代表节点连通、网络可用或 TUN 已就绪。进程意外结束后界面显示失败及退出状态，不自动重启。

关闭窗口即退出应用并清理受管核心。当前停止采用进程组终止（Windows Job Object，Unix SIGKILL），不是平滑关闭；核心正在写入的缓存可能来不及刷新。再次打开只恢复选择，不自动启动。数据目录使用原生文件锁，同一目录不能由多个实例同时管理。

## 日志

stdout、stderr 和壳生命周期消息合并展示，附接收时间和来源。最多保留本次应用运行的 1,000 条记录；单次原始行达到 8 KiB 时拆分，避免无界增长。日志只存内存，退出即清空；取消“跟随最新”可以阅读先前记录。

核心自己输出的文件日志不在此视图采集；其文件位置与轮换由配置和 sing-box 决定。日志可能含服务器地址等信息，分享前自行检查。

## 失败和限制

- 配置检查或版本检查 15 秒未完成会结束检查进程并报错。选错架构、执行权限不足、文件删除或路径失效会明确失败。
- 启动时端口被占用、规则资源缺失及操作系统权限问题，由核心日志说明。
- 设置损坏或 schema 不支持时保留原文件并禁用设置覆盖；按提示修复应用数据目录中的 `settings.json` 后重启。
- 当前没有系统代理切换、订阅、节点选择、托盘、TUN 权限提升和后台服务。配置中的高级功能直接服从 sing-box 和当前操作系统权限；本版不承诺其完整生命周期管理。
- 示例仅绑定回环地址。用户配置可以开放其他监听地址，壳不会改写其内容。
