# 桌面与启动

## Windows 安装范围

NSIS 安装器提供“所有用户”和“当前用户”。有管理员权限的新安装默认所有用户，程序默认位于 Program Files，登记到 HKLM；当前用户安装登记到 HKCU。安装器按系统要求申请授权，GUI 仍以当前用户普通权限运行，TUN 连接仍按需 UAC。节点、配置、受管核心与偏好继续按用户存储。

应用更新明确沿用当前程序的安装范围及位置。旧用户级版本没有范围标记时，更新保留原用户级安装，不静默改成系统级。检测到另一范围已有安装时终止安装并提示：先停止连接、真正退出，卸载旧安装且不勾选删除应用数据，再选择新范围安装。安装器不执行跨范围清理，也不修改其他用户的配置或登录项。

更新保留当前用户的 Run 登记和 Windows 禁用状态；卸载根据自身安装位置确认范围，只清理执行卸载账户下指向本安装的登录项。其他账户已有的登录项由各账户关闭或重新登记。

## 窗口和托盘

关闭主窗口只收起，核心、下载、配置和设置草稿继续保留。首次收起说明返回及退出入口，确认且收起成功才记录。Windows 隐藏至托盘；macOS 收起后使用菜单栏身份，显示时恢复 Dock；Linux 最小化并保留系统窗口入口。托盘建立失败时保留可见窗口，避免无法返回的后台实例。

托盘提供状态、显示主窗口、启动/停止核心、设置、退出。运行状态取真实进程，核心运行中不因维护失败显示成停止；异常可点击查看。投影由原生每秒更新，仅变化时修改菜单，不依赖页面或额外网络检查。文件选择框及退出决定存续时不能收起。

托盘保留贝壳主体，以空闲、处理中、运行和异常形状区分状态，并始终保留状态文字。macOS 使用单色模板，图像变化与模板属性一并更新。清理未完成优先显示异常，启动中有 PID 不冒充连接成功；运行期间核心维护失败仍保留运行状态及问题入口。

同用户、同数据目录重复打开只唤回主实例。重复登录启动不打扰窗口；正在退出时不取消清理，也不初始化第二套核心。

## 两个立即生效的开关

“登录后自动启动应用”默认关闭，开启后在当前用户下一次登录图形桌面时后台启动。手动打开显示窗口。系统登记是唯一事实源，系统禁用、位置过期或读取失败均明确显示；应用不会启动时重新登记来绕过系统禁用。开发和隔离验收模式不可登记真实登录项。

“应用启动时恢复核心运行状态”独立、默认关闭。上次完成启动观察且未主动停止时，下次打开应用尝试恢复；手动启动、托盘启动及回退成功均记录意图。主动停止即使没有 PID，也撤销等待恢复。退出、更新和异常退出不抹掉运行记忆。

恢复只有一次：已有可用核心不等待更新网络；必需核心缺失时等待现有维护准备。无配置、文件失效、准备失败或上次启动未确认时报告原因，处理后手动启动。更换核心/配置、关闭恢复开关或退出使等待请求失效；关闭开关不停止已确认运行的核心。启动观察及一次版本回退规则见[核心与配置](core.md)。

设置 schema 0/1/2/3 备份后迁移至 4，不因旧配置存在推断曾经运行。节点模式恢复固定的最后成功节点参数、分流和规则提交，不套用尚未应用的草稿。Windows/Linux 不在登录恢复时反复弹授权框，提示手动连接；macOS 仅已允许的 helper 可恢复。删除恢复节点撤销依据。恢复、节点与偏好分别合并保存，启动确认写失败停止新连接；停止意图写失败仍执行停止并提示风险。

## 真正退出和更新

托盘退出、设置中的退出应用、Cmd+Q 和系统退出请求进入同一协调器。有草稿时保存/放弃/取消，收起完全不处理草稿。保存失败保留决定和错误；重复请求只保留一份，页面重载后核对新的文档标识，旧回执无效。前端预检无法显示时恢复窗口并报错，不自行放弃草稿。

确认后取消维护与恢复、等待正在执行的任务和登录项写入、停止核心并回收资源，最后退出或交给应用安装器。失败恢复可操作窗口及真实状态，不暗中重启已停止核心。更新重启移除登录来源参数，按恢复开关决定是否恢复核心，见[软件更新](updates.md)。

GUI 是当前用户普通进程，授权 worker 仅管理当前 TUN，不提供登录前连接或崩溃重连。强制结束无法保留未提交表单；节点模式通过通道失联清理，原始配置被 Unix SIGKILL 时不承诺子进程清理。移动/删除 app 或 AppImage 前应停止连接、关闭自启，并在 macOS 系统设置停用网络 helper。实际验收范围见[构建与分发](../distribution.md)。
