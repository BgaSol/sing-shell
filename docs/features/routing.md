# 分流

分流是一张有序策略表。进入 TUN 的流量按可见全局顺序首次匹配，没有隐式的精确域名优先、前缀长度优先或直连优先。显式启用“绕过 TUN”的目标在系统路由层先行排除。唯一“默认规则”固定末尾，不能删除、禁用或排序，只选代理/直连。初始默认代理，并启用国内站点、中国大陆 IP 两条直连策略。

## 规则与编辑

一条自定义策略包含名称、统一出口、启用状态、多个域名和多个 IP/CIDR；任意一项命中即命中该组。域名逐项选择精确或包含子域名；IP 接受 IPv4、IPv6、单地址及 CIDR。空组、同组规范化后完全重复项和非法字段拒绝；跨组重叠允许，由顺序决定。最多 100 个策略和 1,000 个自定义匹配项。

规则编辑使用紧凑模态框。“完成”校验并更新页面草稿；“保存规则”原子提交整张表。运行连接保持固定输入，保存后显示待应用，点击“应用并重连”采用。节点名称/标签和后台来源更新不使分流草稿发生修订冲突。

拖拽和键盘上下移使用同一优先级数组。筛选时保留全局顺序号，只重排可见规则占用的槽位，隐藏规则不移动。页面切换保留草稿，后台读取不覆盖正在输入的内容。

## 自定义直连的 TUN 绕过

自定义规则选择直连后可勾选“绕过 TUN”，默认关闭，作用于整条规则的精确域名、IPv4 / IPv6 地址及 CIDR。沿用已有目标，无需选择程序或声明 RustDesk。固定开源规则、默认规则和原始配置模式不提供此选项；包含子域名的条件须先改为精确匹配。

规则列表显示“直连 · 绕过 TUN”。切换为代理清除绕过，切回直连不自动恢复；禁用规则保留偏好但不生成排除。完成和保存只做本地校验，不解析域名、不提权、不改变现有连接。保存后下次连接采用，运行时点击“应用并重连”。当前实际启用绕过时，即使没有待应用修改，也保留这个入口供刷新地址。

每次连接准备通过独立于本应用 TUN 的系统网络解析精确域名，收集真实 A / AAAA，与手填 IP / 网段共同形成排除范围。当前会话固定这些结果：应用管理的 DNS 对该精确域名返回同一批地址，HTTPS / SVCB 成功空答，避免未排除的地址提示；其他查询类型保持普通直连解析。地址变化后应用并重连刷新，不随 TTL 后台修改路由。

绕过按真实目标 IP 生效，不限端口、协议或程序，优先于普通分流顺序。共享 IP 的其他服务也可能绕过；拖动规则不能改变这一优先级。其他域名不会因为共享真实 IP 就自动改变 DNS 策略，其 Fake-IP 访问仍可能进入 TUN。系统 VPN、防火墙和原有路由继续生效；排除成功不代表目标可达，也不保证任意 NAT 下的远程控制打洞成功。

最多启用 32 个去重精确域名，最终最多 64 个去重排除地址 / 网段；单次查询 5 秒、整批解析 30 秒，准备可取消。没有任何可用地址、超时、响应异常、数量超限或与 TUN / DNS 地址段及 Fake-IP 池相交，均使整次准备失败，不部分应用或静默降级。IPv4-mapped IPv6 须改写为 IPv4，默认路由不能作为排除目标。

候选完成解析和核心检查后才替换旧连接。准备失败保留旧进程、固定 DNS 与排除，新设置继续待应用；候选启动失败的一次恢复复用旧连接实际地址，不重新解析旧规则。关闭、删除或禁用绕过规则后，成功应用撤销对应排除。断开、退出、核心异常及崩溃恢复沿用受控 worker 清理，不留下持久排除路由。

只有开关和目标作为意图保存，解析 IP 不写入用户设置。旧 schema 5 规则缺少此字段时按关闭读取，不要求重新初始化。程序内部缓存、独立 DoH / DoT 或旧 Fake-IP 仍可能使用排除集合之外的地址；必要时重新解析或重启目标程序。本功能不识别程序、不抓包追踪动态对端。

## 编译、保护与 DNS

每组编译为唯一 `policy-<id>` 规则集。自定义多维条件显式使用 logical/or；顶层按数组顺序引用并指定出口，核心负责全部匹配。默认出口仅使用 route.final，不复制节点或引入多节点策略组。

嗅探、DNS 劫持、本机/局域网保护在用户策略之前；解析前后都保护本地地址。核心先解析真实目的地址，再依次匹配所有用户策略，所以靠前的 IP 规则不会因尚未解析而被后面的域名规则抢先。显式代理网段不能与保护范围相交，包含 0.0.0.0/0 与 ::/0；全局兜底应修改默认规则。

DNS 服务器选择只投影域名条件并保留顺序。直连域名使用物理网络解析路径，代理域名经节点访问 Cloudflare HTTPS，未命中按默认出口。混合组只投影域名部分，纯 IP 规则不在解析前决定 DNS 出口。IP 规则可能在解析后改变连接出口；浏览器自有 DoH、不可嗅探域名和其他 VPN 的边界仍服从核心及系统行为。

## macOS 系统 DNS

节点模式连接时，按需授权 worker 在 SystemConfiguration 登记独立随机键的临时默认解析器，指向隧道 DNS，不修改 Wi-Fi／以太网的持久 DNS 偏好，无需用户设置。登记后核对有效系统解析器、刷新缓存，再确认连接。核心仍负责 DNS 解析和分流。

节点主机名及直连 DNS 使用官方核心的物理接口 scoped 上游；接管前后必须存在独立入口，避免回退到自身隧道。IPv6 链路本地 DNS 保留接口作用域。运行中低频复核，切网后不能确认入口或接管失效就清理并提示重新连接，不自动重连或争抢其他 VPN 的优先级。

断开、取消或核心退出统一释放本次临时解析器并刷新缓存。worker 被强杀时由系统会话回收临时键，核心残留另按受保护记录处理；不扫描删除其他应用的 DNS 键。更具体的系统域名范围、`.local` 和搜索域仍服从 macOS 行为；普通私有域名遵循现有 DNS 分流规则。原始配置与外部核心不使用壳的 DNS 接管。

## 固定来源与自动更新

固定五项：国内站点、Google、GitHub、Telegram（SagerNet/sing-geosite），中国大陆 IP（Loyalsoldier/geoip）。一个来源只能添加一次，用户不能输入任意远端地址。包内附全部固定 SRS、摘要、可编辑来源及 GPL / CC-BY-SA 归属，基础使用可离线。

已添加来源默认每天更新，可关闭或改为 6 小时、每周。禁用匹配不关闭更新偏好；移除并保存来源后撤销其偏好。增删与偏好合并在一次设置写入完成，保留其他来源的并发偏好。自动任务由应用既有后台循环调度，一次只准备一个来源，失败退避，不补跑所有错过的周期。

更新先解析不可变提交，再下载固定文件、核对身份/大小/摘要并由官方核心实际加载验证，成功后原子发布版本索引。失败保留旧版本、用户策略与当前连接。普通下载采用已保存的下载网络偏好；授权 worker 从受保护缓存、包内内容或固定上游独立确认同一版本，不相信普通缓存自填 hash。

规则版本和更新状态独立于 routingRevision，不覆盖草稿、不改出口/启用/排序、不自动重连或替换运行文件。连接冻结具体版本，当前/候选/恢复引用及包内版本保留，无引用内容按固定来源目录回收。来源完整性不等于涵盖所有产品域名。

## Fake-IP 与 IPv4 兼容

节点模式内置固定 IPv4 Fake-IP 池 198.18.0.0/15。代理域名的 A 查询分配虚拟地址，AAAA 成功返回空回答；明确直连域名继续真实解析。核心还原域名后取得真实目标地址，再按原全局顺序匹配域名、IP 和站点策略。Fake-IP 不代表最终必走代理，也不代表真实出口只能用 IPv4；纯 IP 规则仍不在 DNS 前选择出口。

localhost、本地单标签名字、.local 及反向查询使用本地解析。私有完整域名按既有域名规则处理；系统搜索域、更具体解析器、独立 DoH/DoT、HTTPS/SVCB 地址提示和旧缓存仍有各自边界，不能承诺全部请求经过 Fake-IP。

设置 → 网络提供一个“IPv4 兼容模式”，默认关闭。开启后进入 TUN 的业务域名只解析真实 IPv4，公共 IPv6 字面请求由核心明确拒绝，本机/局域网 IP 保护直连优先。仅 IPv6 公网目标因此不可用；部分仅 AAAA 的私有完整域名也可能受限。绕过 TUN 的目标及其固定地址回答继续使用系统双栈网络，不受该开关约束。节点服务器引导解析独立，可继续使用 IPv6。TUN 仍接管双栈，不修改网卡 IPv6 或持久 DNS。

保存连接设置不重启核心；运行中点击“应用并重连”采用，未连接时下次生效。切换节点保留全局偏好；失败恢复旧输入时显示旧实际模式。原始配置自行控制，不注入 Fake-IP。

真实节点地址、具体 IP 规则或物理路由占用 Fake-IP 池时，准备阶段报错并保留原设置及现有连接，不自动改池。宽 IP 规则仍只匹配还原后的真实地址。
