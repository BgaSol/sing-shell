# 软件更新

## 核心自动安装和更新

v0.3.0 起，新安装默认使用应用管理的官方 sing-box。首次没有核心时自动下载，允许同时导入配置；准备完成不自动运行代理。默认开启“自动更新核心”，在应用运行期间每天检查正式稳定版，自动下载、校验和准备，应用退出后不继续后台工作。

应用和核心各有检查周期与失败状态。首次安装在本地恢复后立即开始；普通更新成功/无新版后约 24 小时再检查，临时网络失败约 15 分钟后重试。调度每分钟判断，停止、准备完成及设置改变也会唤醒。页面打开或重载不另发维护任务。

新版准备好且核心已停止时，检查当前配置后自动采用，无需重启壳；核心运行中保留当前进程，新版下次启动前生效。下载期间已有版本可以照常启动。首次启动确认和一次回退见[核心与配置](core.md)。

正式候选按 SemVer 比较，跳过草稿与预发行。最新正式候选缺本机包、缺摘要或不兼容就显示原因，不静默寻找旧发行。核心程序验证归档摘要/大小、路径和解包限额、PE/ELF/Mach-O 原生架构、实际版本；采用前再检查真实字节与配置。配置不兼容时保留旧版和已下载材料，可以改正配置后重试，不修改用户文件。

关闭“自动更新核心”并保存后，停止自动来源的在途任务，并禁止尚未提交的自动采用；已准备候选也不会在下次启动偷偷生效。明确手动发起的更新可以继续。首次获取必需核心、恢复已选版本的文件不属于后续自动升级，开关关闭仍可执行。

取消维护会停止当前任务，并暂停本次会话的自动重新发起；可以明确重试或下次打开恢复。取消信号不等于收尾已完成。网络与限流有界重试，坏包和明确失败候选不会被每 15 分钟重复下载。磁盘写入失败会暂停本次会话的自动写入，处理后重试。

“检查核心”只发现官方候选，不下载、采用或解除失败暂停；已有准备结果不改变检查的含义。“更新核心”先完成已有准备结果，“重试准备核心”按实际失效阶段继续：有效程序直接采用，有效归档本地重新准备，归档无效才重新获取同一已核验资产。配置不兼容保留准备材料，检查成功不抹去尚未解决的采用错误。

## 外部核心、修复和恢复

外部核心只由用户手动管理，即使路径失效也不接管；v0.1.0/v0.2.0 的外部选择照旧。切回应用管理需要用户明确操作，缓存里存在 ready 不能代替接管意图。

受管程序保留当前、至多一个上一版本和一个准备候选，不提供多版本列表。新版本首次启动确认前不自动连续采用下一个版本。中断的 `.part` 不代表完成，恢复必须验证实际字节。

当前文件缺失/损坏时优先恢复可核验的上一版本，否则获取已选版本的同一官方资产。它是同版本修复，不自动升级至别的版本；来源身份变化则失败并要求手动处理。仅在核心完全停止、选择仍匹配且 staging 完整验证后替换损坏文件，不能覆盖正常或运行中的程序。

首次启动状态持久化。若应用在确认之前中断，下次优先恢复可验证的上一选择并提示；没有可回退版本则等用户明确重试。检测到未确认的启动时暂停本次自动恢复，也不反复采用已失败候选。损坏设置保留原件，不通过重置设置掩盖错误。

本地散列不冒充官方真实性证明，新下载必须具备上游证据。schema 5 不读取旧代设置，保留原件并要求显式备份初始化；回装旧应用需恢复对应原件。

采用按校验材料、发布程序、原子提交选择、消费准备记录的顺序执行。程序已发布但设置保存失败时保留材料，重试可继续提交；设置已经提交但准备记录清理失败时，核心仍可用，显示收尾警告，下次按同一来源和摘要完成清理，不重置试运行或丢失上一版本。单个准备槽未完成前不开始第二个候选。

采用同时核对运行操作和文件任务的取消信号。设置写锁内最后核对资格之前接纳的取消、退出、来源或偏好变化禁止提交；之后允许短暂的原子设置写入完成，如实展示结果。运行、待清理网络或检查资源仍禁止采用。确定的采用错误暂停自动重放，避免后台反复尝试相同失败。

节点模式的生成配置也参加采用兼容检查，当前只允许 1.14.4–1.14.x 的 TUN 能力档。授权 worker 不执行用户可写的受管副本，而是独立准备同版本官方资产。运行时只准备更新；节点/分流保存和规则更新均不改变当前连接。站点更新是独立手动操作，不混入应用待重启列表。

## 应用更新

Sing Shell 应用更新继续独立处理：自动检查只发现版本，需要手动下载，验证独立 Tauri updater 签名后明确“重启并更新应用”。核心不计入待重启项，也不随应用安装动作一起切换。应用重启会取消后台维护、等待任务、停止代理，重新打开后按[启动设置](desktop.md)决定是否恢复核心。Windows 安装器接管前已完成任务等待和核心资源回收，安装失败恢复可操作界面，保持实际停止状态。

应用源是公开的 `BgaSol/sing-shell` 同一仓库，清单为 `core-update.json`；核心源为 `SagerNet/sing-box`。应用使用本项目独立公钥，核心使用原始官方 GitHub HTTPS API 的资产摘要，不能只相信同时提供包的第三方镜像。客户端不需要维护者凭据，不内置 PAT 或私钥。

受控 TUN 的 1.14.4 引导元数据已随源码固定为当时官方资产摘要；其他版本仍向官方 API 核实。网络 worker 禁用自定义镜像，不继承 token、密码或动态库注入变量。应用更新交接必须先结束授权连接、释放接口及旧 worker，不能只停止 GUI 内的进程快照。

| 安装形式 | 应用更新方式 |
| --- | --- |
| Windows NSIS | 官方 updater 验签并交给安装器，沿用当前程序的安装范围和位置；系统级更新按需管理员授权 |
| macOS 已安装 app | 官方 updater 替换可写位置的应用；只读 DMG 应先正常安装 |
| Linux AppImage | 官方 updater 替换当前可写 AppImage |
| Linux DEB/非 AppImage | 使用系统安装方式，应用不调用 sudo 或修改系统包库 |

v0.2.0 已有 updater，可在线升级到本版。v0.1.0 没有更新客户端，需先手动下载安装。updater 签名不替代 Windows 发行商证书或 macOS 公证，目前未提供后两项。

## 下载线路与设置

复用原始地址和启用的自定义/内置备用线路。API 与文件健康分开记录；核心摘要元数据必须来自原始 GitHub API，包字节可走备用线路。原站不可获得时明确失败；本地已验证材料不依赖更新网络，可以离线恢复或采用，但用户配置检查可能需要它自身的资源。

可以停用内置线路、编辑/排序/删除最多 10 个自定义 HTTPS 前缀。诊断只测试所填线路，不自动换线。保存后的线路用于新任务，在途任务继续使用接纳时快照，旧结果不污染新的线路健康状态。

应用检查、核心自动更新和网络偏好需要保存后生效。后台核心版本变化不会造成网络草稿冲突；真正的并发偏好保存失败保留输入。关闭窗口保留草稿；真正退出和更新先预检，有草稿才提供保存、放弃或取消。退出请求核对前端文档与请求标识，事件丢失由快照补取。状态刷新不重建输入表单、详情或日志滚动区域。

生产请求只接受无凭据 HTTPS，受控重定向不传播测试 token。元数据限制 2 MiB，包限制 512 MiB；读取、下载总时限、临时校验与取消均有边界，中断和坏包换线时从头获取，不拼接不同来源字节。

包缓存位于 `updates/app` 和 `updates/engine`，核心版本程序位于应用数据目录的 `engines/sing-box`。程序路径由应用推导，清理不跟随受管目录链接，不触碰外部程序和配置。具体签名与验收见[分发](../distribution.md)。
