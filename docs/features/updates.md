# 软件更新

v0.2.0 起提供应用与受管 sing-box 的独立更新。v0.1.0 没有更新客户端，第一次需要手动下载安装支持本功能的版本；既有 v0.1.0 附件保持不变。

## 检查与下载

“软件更新”展示 Sing Shell 应用和 sing-box 核心。可检查全部或单项、下载可用项、重试及取消下载，显示版本说明、真实字节和失败原因。

默认开启每日检查。启动先恢复缓存，约 10 秒后尝试检查；全量成功后约 24 小时检查，部分失败/失败约 15 分钟后重试，调度每分钟判断一次。手动单项检查不推迟其他组件的每日周期。关闭开关并保存后不再接纳新的自动检查，在途任务继续收尾。

自动检查只发现版本，不自动下载、切换程序或重启；进入页面不会另开检查。页面关闭或重载不取消后台下载，退出应用则取消并等待收尾。最多同时下载两个组件，重复请求由后端拒绝。

正式标签按 SemVer 比较，跳过草稿和预发行。首个正式候选缺清单、坏签名、缺本机平台或网络失败就显示原因，不静默选择历史包。失败保留已有候选，已准备更新保持待应用，不显示为“已是最新”。

## 应用与核心的边界

| 对象 | 行为 |
| --- | --- |
| Sing Shell 应用 | 从公开的 `BgaSol/sing-shell` 正式发行读取清单和包，使用本项目独立的 Tauri updater 公钥验签 |
| 应用管理的 sing-box | 从 `SagerNet/sing-box` 获取命令行核心，检查上游摘要、原生架构、实际版本及当前配置 |
| 外部核心 | 手动管理。更新功能不覆盖、移动或删除该文件；v0.1.0 的选择自动迁移为外部核心 |

尚未采用受管核心时，点击“查找官方核心”，再下载和明确应用，即可采用应用管理的版本。候选配置检查失败时保留原选择和运行；切换后保留一个上一版本，不提供历史版本市场。

配置继续引用用户原文件，工作目录仍是配置父目录，不上传或改写。准备后配置改变会在应用时重新校验，启动时也再次检查。无配置时可先准备官方程序，启动仍需导入有效配置。

## 重启并应用

下载和验证完成后显示待应用。点击“重启并应用”会停止当前代理；重启后仍需手动启动核心。普通启动同样不自动运行核心。

应用前先离线核对包、签名、平台、核心版本和配置。验证失败不提前停止当前核心；验证完成后封闭新操作、确认核心退出，再切换选择或交给官方安装器。安装阶段不依赖仍在运行的代理或网络请求。

两个组件各自提交，不承诺跨组件事务。如果核心选择已切换、应用安装随后失败，界面保留实际分项结果，核心维持停止，不伪装全成功或全回退。停止失败不继续安装，可以重试。

| 平台/安装形式 | 应用更新 |
| --- | --- |
| Windows NSIS | 官方 updater 验签后交给安装器，权限服从系统 |
| macOS 已安装 app | 官方 updater 替换应用；只读 DMG 或无写权限位置需先正常安装 |
| Linux AppImage | 官方 updater 替换当前 AppImage，路径需可写 |
| Linux DEB / 非 AppImage | 提示使用系统安装方式更新；应用不调用 sudo 或修改系统包库 |

只有实际运行版本变化才确认应用升级。updater 签名与 Windows 发行商证书、macOS 公证不同；目前未提供后两项。

## 缓存和失败恢复

包和版本化准备记录位于应用数据目录 `updates/app`、`updates/engine`。`.part` 不算完成；准备记录最后提交，恢复和安装前重新核对实际字节。应用包使用官方验签，核心使用上游 SHA-256、架构和版本检查。损坏、跨平台及不属于当前应用版本的缓存不能成为 ready。

断网时已验证缓存可以恢复并离线应用；新下载仍需读取发行元数据。失败保留有效候选和可重试材料，配置损坏不覆盖原设置。

## 下载网络与设置草稿

原始地址优先，失败后按启用情况尝试自定义及内置备用地址。API 与文件健康分别维护；诊断只测试输入地址，不自动换线。可停用内置地址、编辑/排序/删除最多 10 个自定义 HTTPS 前缀。

上游 sing-box 的摘要元数据必须来自原始 GitHub HTTPS API，不能只信任同时提供包的第三方镜像；包字节可经备用线路，仍核对原始摘要。原站元数据不可获得时明确失败，已有离线缓存不受影响。

修改偏好后需要保存；在途任务继续使用原设置，后续任务使用新值。修订冲突/保存失败保留输入，可载入最新设置。退出时有草稿才提供保存、放弃或取消；进度刷新不重建表单、详情和滚动容器。

客户端不需要维护者 GitHub 凭据，不内置 PAT 或私钥。生产请求仅接受无凭据 HTTPS，受控重定向不向镜像传播测试 token。元数据单响应限制 2 MiB、包限制 512 MiB，读取与取消有期限。中断或坏包后清除本次临时下载，换线路从头获取，不拼接不同节点的数据。

其他行为见[核心与配置](core.md)，签名和验收见[分发](../distribution.md)。
