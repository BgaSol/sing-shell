# 平台适配与网络生命周期代码整改方案

状态：代码审查与整改设计，尚未实施。日期：2026-11-26。审查基线：`main@f0f03fc`，包含当天发行至 v0.5.3 的代码；工作区已有的 [macOS TUN DNS 设计](macos-tun-dns.md)仍未实现。

## 整改结论

本次围绕一条完整链路收敛：**一次连接的资源由谁持有，什么条件算就绪，什么证据算清理完成，以及这些事实怎样到达页面、托盘和安装器。**

保留现有 Tauri／Rust 架构、SessionService、RuntimeService、按需授权 worker 和退出协调器，进行有限重构。重点消除分散的失败清理、重复的状态判断和跨职责平台调用。macOS DNS 补齐接入同一条生命周期，避免以后每增加一项系统资源就补一套分支。

不新增用户操作、持久后台服务、配置框架、运行时或生产依赖；不升级设置 schema、不改变节点格式和分流语义。订阅、测速、策略组、系统代理、崩溃重连均不进入本次范围。

## 已追踪的链路

| 链路 | 当前入口与关键调用 |
| --- | --- |
| 手动／托盘连接 | IPC 或托盘 → `SessionService::action/start_owned` → 节点模式 `Tunnel::start` 或原始配置 `RuntimeService::start`。 |
| TUN 授权 | `Tunnel::request` 的控制线程 → 平台 `authorization::connect` → 系统授权启动同一程序 → 对端身份核验与握手 → 发送闭合类型连接参数。 |
| 受控核心与网络 | worker 接收请求 → 独立验证官方核心／规则 → 生成并校验配置 → RuntimeService 持有子进程 → 平台观察接口、地址和路由 → 返回运行事实。 |
| 停止与异常 | 用户停止、启动取消、核心退出、控制通道断开 → worker 收尾 → 停止确认／关闭确认／通道 EOF → 控制端确认 helper 及授权启动器退出。 |
| 退出与更新 | 托盘、设置、系统退出 → 退出协调器 → 草稿预检 → 封闭接纳并等待任务 → `SessionService::stop_internal` → 交给退出或官方 updater。 |
| 桌面与恢复 | 启动来源归一化 → 实例锁／唤回 → 原生登录项事实 → 一次恢复意图；页面与托盘读取 Session 快照。 |
| 发行验收 | 目标矩阵 → Check／TUN／打包 → 原包安装、升级、真实核心与退出 → 按源码、包摘要和验证范围记录证据。 |

审查覆盖上述调用方、所有权、错误路径和相关测试。未对全部协议解析、下载传输、规则资源或每条历史提交逐行重审；这些模块只有被整改接口影响时才调整。

## 问题与证据

以下区分已复现的缺陷、代码可见的不一致与尚需失败注入验证的风险，不把静态审查推断当成实机结论。

| 优先级 | 发现 | 证据及影响 |
| --- | --- | --- |
| P0  | macOS 系统 DNS 未纳入 TUN 就绪 | 137 Mac 已复现系统解析绕过 TUN；[网络观察](../../src-tauri/src/platform/network.rs#L194)只有接口、双栈和路由，[worker](../../src-tauri/src/session/tunnel/worker.rs#L93)据此发布 Running。属于完整链路缺口，DNS 设计已单列。 |
| P1 | 启动失败与正常停止执行不同清理 | [worker 启动失败](../../src-tauri/src/session/tunnel/worker.rs#L120)只停止 runtime 并检查接口；[正常停止](../../src-tauri/src/session/tunnel/worker.rs#L158)另做恢复记录、配置删除与接口等待。前者没有在该分支删除生成配置，清理错误也被原始错误盖住；后续停止可能补做，不能因此省略失败路径。 |
| P1 | 授权进程启动后到 Connection 构造前存在所有权空档 | [Windows](../../src-tauri/src/platform/authorization.rs#L227)拿到进程句柄后，等待管道期间取消／超时直接返回；[Unix](../../src-tauri/src/platform/authorization.rs#L435)已有子进程后，接收与状态查询仍可提前返回，macOS 二次取 token 也可能失败。尚不能据此断言产生持久孤儿，但这些路径未统一经过 `Connection::finish`。 |

| P1 | 测试覆盖了转发，未覆盖系统域名解析入口 | [网络集成](../../scripts/network-integration.mjs)主要访问两个直接 IP，节点服务器也是回环 IP；这能验证加密转发和清理，却不能发现系统 DNS 绕行、域名节点冷启动或解析回环。 |
| P2 | Session 与 Runtime 仍用手工标记同步 TUN 占用 | [Session](../../src-tauri/src/session/mod.rs#L362)维护 `network_owned`，[Runtime](../../src-tauri/src/runtime.rs#L162)、核心采用和节点删除据此阻止变更；真实资源在另一 worker 中。该标记有必要保护调用方，但应有单一所有者，不能继续在成功／失败分支手工配对。 |
| P2 | 状态含义与运行输入未完全收敛 | [Session 快照](../../src-tauri/src/session/mod.rs#L102)把 Tunnel Phase 改写为 runtime 字符串，页面和托盘再次判断；`applied` 仅在成功启动时赋值，停止后快照仍可能携带上一运行节点。需分清“正在运行”与持久的“上次成功连接”。 |
| P2 | Windows 安装事实属于错误的模块 | [updater](../../src-tauri/src/updates/application.rs#L47)调用 `login_startup::installation_scope` 判断安装范围。升级安装与登录项本是两个用例，应该共用底层安装事实，而非互相依赖。当前行为已有实际包测试，移动时必须保留。 |
| P2 | 旧实现残留在文档和报告中 | [桌面合同](../features/desktop.md)仍称 macOS 已允许 helper 可恢复、移动应用前需在系统设置停用网络 helper；代码 `can_resume()` 对受控 TUN 返回 false。[包验证脚本](../../scripts/verify-package.mjs)仍使用 launchd approval 描述当前网络验收。容易再次把 DNS／进程错误误判为用户未允许。 |

## 目标边界

```text
页面／托盘／一次恢复／退出与安装
                 ↓
SessionService：接纳操作、运行意图、一次回退、成功提交、统一对外状态
           ↙                         ↘
原始配置 RuntimeService        Tunnel：授权控制会话及真实关闭确认
                                      ↓
                             Worker：本次网络资源及统一清理
                                      ↓
                             RuntimeService：核心进程及日志

platform：授权启动、身份、进程、安装事实、接口／路由、macOS 临时 DNS
sing-box：协议、DNS 解析、分流、路由设置及实际转发
```

- **SessionService** 决定运行哪个模式、何时提交成功、如何撤销意图；不直接执行提权或解析系统命令输出。
- **Tunnel 控制端** 持有授权会话、控制线程及退出证据；不凭 PID 消失或 socket EOF 单独宣布网络全部清理。
- **Worker** 持有本次启动任务、生成配置和平台资源；RuntimeService 继续持有真实 Child、进程组和日志 reader。机器级租约覆盖所有资源收尾。
- **平台适配** 返回事实和具体操作结果，保留各系统的身份与授权差异。只共享相同的业务约定，不建立可插拔平台服务体系。
- **页面与托盘** 可以保留不同文案和图标，但使用同一会话阶段与操作许可；安装器必须等待同一清理结论。

## 整改一：授权进程从创建起就有所有者

将 `authorization.rs` 中 Windows、Unix 启动与安全检查按现有风格拆成具体平台文件。保留当前 Channel、闭合消息和握手，不统一不同操作系统的安全机制。

拿到任何真实进程句柄／Child 后立即纳入现有授权连接所有者，再执行可失败的等待、认证和协议交互。允许该所有者处于“只有启动器、尚无已认证通道”的准备阶段；不建立第二个独立生命周期。macOS 的可信 audit token 应在身份核验成功时一并交回，避免之后再次获取失败造成所有权丢失。

所有错误路径都先关闭可控端点并进入同一个收尾入口。终止对象限于本次明确拥有的启动器；不终止无法认证的对端，不通过进程名扫描管理员进程。Windows 保留内核句柄，macOS 保留运行审计身份与授权启动器，Linux 保留实际 Child 的退出观察。

调用方超时表示“尚未确认完成”，保留原控制线程／所有者供停止重试；底层无法读取退出事实时不得把未知当已退出。退出检查借用所有者，仅在确认结束后取走进程资源，避免查询报错顺带丢掉句柄。`Drop` 只作兜底，成功路径和失败路径都必须显式完成收尾。

把生产控制端与授权探针重复的 `Quit → Stopped → Closed → EOF → helper/launcher exit` 收敛为同一具体关闭函数。探针继续只验证授权与退出，不启动核心；它调用产品函数验证产品路径，不另写一套近似流程。

## 整改二：worker 使用一条可重试的清理链

以现有 Worker 为本次网络资源的唯一所有者。可用一个小的具体资源结构收拢生成配置和 macOS DNS 会话；不引入 `Resource` trait、可注册清理栈或通用事务框架。

启动任务只负责按顺序获取资源并交回结果，worker 主循环负责结束任务、发布运行／失败状态和驱动清理。通过已有 JoinHandle 或单一结果通道交接；不让启动线程和停止线程分别重写最终状态。停止必须等待原启动任务完成，取消之后不能再发布 Running。

所有结束原因共用如下顺序：

1. 标记取消并等待启动任务实际结束。
2. 释放本次临时 DNS 并确认自身键消失，处理缓存。
3. 优雅停止核心，必要时使用现有进程组／Job 强制结束，等待日志资源。
4. 按既有受保护记录恢复残留，确认本次接口及相关网络资源释放。
5. 删除本次生成配置，最后清除恢复记录；结束整个授权会话时才释放机器级租约，应用配置时的内部停止继续持有它。

顺序有依赖的步骤不能越过：启动任务未结束不能销毁其资源，核心仍可能读取文件时不提前删除配置。某项独立清理失败仍尝试其余可安全执行的清理，保留未完成资源用于重试。

原始错误与清理错误分别保留：错误结果至少表达“哪里失败”和“是否清理完成”，不新增一套泛化错误系统。只有资源全部确认释放，才发布 Stopped 或已清理的 Failed；其余保留 CleanupRequired，禁止新连接和更新交接。运行中更改配置可复用认证通道，用户断开／退出则结束整个授权会话。

复用现有受保护 `network-process.json`，不迁移其格式、不降低 PID 启动身份与路径检查。worker 被强杀后，临时 DNS 回收和核心残留恢复分别验收，不用前者替代后者。

## 整改三：把“就绪”和“已清理”定义完整

### 一份内部 TUN 规格

将当前重复出现的接口名、双栈地址、DNS 地址和受控核心版本范围归到生成配置所属模块的一组内部常量／具体规格。配置生成和系统观察读取同一来源；控制端与 worker 都调用同一个能力判断函数，但管理员边界仍独立重新校验。

保留官方核心引导元数据及摘要验证，不把“去重”变成信任 GUI 提供的路径、配置或兼容结论。测试可明确注入受控规格，不让生产环境变量绕过身份或来源校验。

### 平台观察使用一致的业务含义

- 接口：确认本次预期接口及对应地址；只有同名或只有某个地址族不算完成。
- 路由：分别确认 IPv4、IPv6 默认覆盖。default 或成对的两个半区路由可以满足，单个 `/1` 或一条局部路由不能满足。Linux 同时考虑策略路由及其规则选择，不能简单要求 main 表中出现默认路由。
- macOS DNS：按既有 DNS 设计确认本次临时解析器和独立物理 DNS 入口。动态存储写入成功不能单独代表系统正在使用该解析器。
- 清理：检查本次资源是否释放，不删除其他接口、DNS 键或其他软件的路由。无法确认归属时报告冲突，不能通过全局清空网络来恢复。

将系统输出解码和“是否满足条件”的判断拆为很小的纯函数，用真实平台样本覆盖字段缺失、局部路由、半区缺失和策略表。外部只读命令必须固定程序及参数、限制等待和输出；观察失败保留 unknown/error，不用空默认值伪装已清理。

macOS 临时解析器的创建、缓存及切网检查遵循 [DNS 专项设计](macos-tun-dns.md)，在整改二的资源所有者中落地。首要技术门槛仍是 137 Mac 上验证真实系统解析、节点域名无回环及进程退出回收；本次不另选永久改 DNS 的备用实现。

## 整改四：状态、平台事实和交付同步收敛

### 单一对外状态

保留现有有限阶段，在 Rust 内用枚举进行判断，TypeScript 改为对应的有限联合类型。Tunnel Phase 到会话／兼容 runtime 状态的映射只在 Session 的一个位置执行；页面不再通过 PID 或提示文字重新推断连接成功。

不复制一套“会话管理器”。Runtime 快照继续表达进程事实，Session 快照表达整个连接事实；若保留兼容字段，必须由同一投影生成。托盘图标、按钮许可、错误状态及安装阻塞都从该结果读取，配置／更新维护错误与当前网络阶段分别表达。

将现有 `network_owned` 的更新集中到 Session 持有的占用租约中，覆盖准备、运行、取消和清理待完成状态。它取代分支中手工配对的布尔写入，不增加新的接纳管理器；请求返回或失败不释放该租约，只有真实关闭确认后释放。不能直接用操作票据代替：票据结束不等于连接停止。核心自动采用和节点删除继续能检查占用，不增加 CoreService 对 SessionService 的反向依赖。

确认停止后清除内存中的 `applied`；持久的 `startup.lastConnection` 仍遵循现有恢复意图规则。应用失败恢复上一连接时先在当前用例保存旧输入，不能靠停止后遗留的“正在运行节点”字段取回。用户主动停止撤销恢复意图，内部停止、退出和更新不误抹历史。

顺带删除已被模式分派排除的重复分支，例如原始配置启动路径中的 generated 构造；不扩大成两个启动模式的全面合并。核心首次回退、应用连接回退仍分别最多一次，不互相递归重试。

### 安装、登录项与旧迁移各有归属

- 将 Windows 安装位置／范围识别移至 `platform/installation` 的具体 Windows 实现，供 updater 和登录项共同读取。保留当前用户、所有用户、自定义目录、旧安装无标记和跨范围冲突语义；NSIS 保留实际执行时的再次检查。
- 继续共享现有 macOS bundle 检查。完整 bundle、稳定安装位置和允许请求网络授权的位置是不同条件，由具体调用方决定；通用错误不夹带“登录启动”等其他用例文案。
- 网络旧 SMAppService 迁移继续隔离在 legacy 模块，旧 plist 只用于撤销已知闲置作业。保留归属、PID 和活动数检查，当前版本仍需兼容升级，不提前删除迁移。
- macOS 登录启动的 `SMAppService.mainApp` 仍是当前实现，与旧网络 daemon 分开；Linux XDG 自启、AppImage 外层路径、Windows 系统禁用状态及平台窗口行为不因整改改动。
- 登录项退出等待继续由 Admission 管理；当前没有调用的 `Service::settle`／stopped 标记可在确认全部调用后删除，避免两套退出接纳机制。

### 验收执行路径明确

保留现有五个原生目标：Windows x64／ARM64、Linux x64／ARM64、macOS ARM64。macOS x64 不属于当前发行矩阵，本次不扩平台。ARM64 仍使用原生运行器，构建通过不替代实际包与系统验证。

整理现有网络脚本中的两种实际执行方式为明确的测试模式：可丢弃运行器提权入口、普通用户安装应用的系统授权入口。二者复用产品通道、身份和生命周期，隔离方式与可执行破坏性测试的范围独立；环境变量只选择验收方式，不关闭生产校验。

报告分别记录授权交互、身份握手、直接 IP 转发、系统 DNS、异常回收、安装升级和托盘视觉，不把一个总 passed 外推为全部验证。复用原包时保留包源码与验收工具源码两个身份；首次失败与重跑均保留。删除当前报告中旧 launchd 激活措辞，历史发行记录保持原证据。

按依赖顺序实施，每一步是一项完整主题；不先大搬文件，再等最后一步才恢复功能。

| 步骤 | 改动与边界 | 完成标准 |
| --- | --- | --- |
| 1. 固定行为与故障回归 | 增加授权创建后取消／超时、失败清理、部分路由和状态投影的最小回归；用隔离 Mac 原型验证临时 DNS 可行性。 | 能明确区分当前缺陷与已有通过的保护；单元测试不提权、不改真实网络。 |
| 2. 收拢授权所有权 | 平台启动文件拆分、从创建起持有进程、共用完整关闭协议；不改身份策略。 | 创建后每个失败点都收尾或保留同一个所有者；拒绝／取消不留下可接管的新连接；身份失败前不发送节点。 |
| 3. 统一 worker 清理 | 启动结果交接、资源所有者、单一清理、错误保留与时限。 | 失败、取消、正常停止和失联走同一清理链；迟到启动不能反转停止；超时后重试仍操作原资源。 |
| 4. 补全网络合同 | 统一内部规格、三平台观察语义、macOS DNS 资源；更新快照及文案。 | 137 系统 DNS 故障回归通过；局部／半区路由不会误判 Running；DNS 已释放不冒充整套网络已释放。 |
| 5. 收拢调用边界 | 单一状态投影、占用租约、applied 生命周期、Windows 安装事实、删除失效标记。 | 核心采用和节点删除仍被真实占用阻止；停止后页面、托盘、更新和运行输入一致；安装范围与登录禁用状态保留。 |
| 6. 原包回归与文档收口 | 整理现有验收入口与报告，更新正式合同并删除已完成计划。 | 五原生相关检查和原包验证通过，macOS 普通用户授权／系统解析单列；未执行项有明确记录，确认后才进入发行。 |

第 1 步 DNS 原型若不能满足系统解析、无回环和退出回收三个条件，暂停 DNS 集成并修订专项设计，其余所有权整改可以继续；不以未验证路径进入发行。每步一主题提交，可独立审查，禁止跨步骤顺便改协议语义或设置迁移。

## 必须保留的回归与新增验证

| 层次 | 验证内容 |
| --- | --- |
| 纯逻辑／失败注入 | 请求授权后取消、管道／socket 接收失败、认证失败、启动器先退出、退出状态未知、重复停止、停止超时后重试；生成配置创建后任一点失败均有明确所有者。 |
| 生命周期集成 | 页面／托盘／恢复启动、准备中停止、保存成功依据失败、应用配置失败恢复一次、核心退出、控制端失联；断言不能重入及不能更新交接。保留当前“读取状态不执行清理”回归。 |
| 平台观察 | Windows 地址与路由样本、Linux 策略路由／缺失命令／错误 JSON、macOS scoped 路由／半区缺失／解析器冲突；读取失败不等于空网络。 |
| macOS 真机 | 域名节点冷启动；系统 getaddrinfo 与普通应用解析 A／AAAA；直连和代理 DNS；正常断开、取消及切网。worker 强杀回收在可丢弃 Mac 执行，用户机器不注入崩溃。 |
| Windows 实际包 | CurrentUser／AllUsers 及旧用户级升级、自定义中文空格路径、跨范围冲突、保留系统禁用登录项、停止 TUN 后安装、真正退出与卸载归属。 |
| Linux 实际包 | DEB／AppImage 的路径、自启、最小化返回、pkexec／polkit；策略路由、双栈转发和异常清理；DEB 不借应用 updater 提权更新。 |
| 桌面状态 | 空闲、授权、准备、启动、运行、停止、失败及 CleanupRequired 对应页面和托盘；维护失败不把运行图标改为停止，托盘失败仍有可返回的窗口。实物视觉与系统主题单列验收。 |
| 数据与安全 | 设置和节点原字节、原始配置、外部核心保持；日志／快照不泄露凭据；同安装同构建校验、随机私有端点、受保护核心摘要与机器租约均保留。 |

实现涉及的提交运行 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run build`，再执行被影响的真实核心、原生网络和原包验证。使用确定的受控 DNS／节点及失败点，避免以更长 sleep 或失败后无条件重跑替代修复。

## 停止扩张的边界与风险

整改完成应体现为：资源归属清晰、失败与成功共用清理、就绪谓词完整、平台事实有唯一来源。文件拆分和行数减少不是验收目标。只对真实重复点建立小函数／具体类型，不建立统一平台 trait、大型状态机库、事件总线或通用后台任务框架。

主要风险是停止时序和资源交接变化，必须先有失败回归，再改所有权；macOS 临时 DNS 与官方核心本地解析的组合仍需实机验证；Windows 安装逻辑移动必须保持旧包升级路径。当前计划只读代码与已有发行证据，不表示本轮已经重跑跨平台、授权或网络验收。
