# 节点、TUN 与分流的代码整改方案

状态：已批准实施，正在进行 P0。2026-11-26 基于源码 `4a318e1d2e7863289e7534c1355a3aab2bc86c12` 追踪现有链路。用户已授权完成实现并发布 latest；尚未通过的阶段不能报告完成。

## 1. 目标、产品合同与整改边界

将主要运行入口从“选择完整配置文件并运行核心”转为“导入节点、选择一个出口、编辑全局分流、启动 TUN”。由应用生成受控配置，实际协议、路由、DNS 和转发仍由 sing-box 执行。

已确认的产品行为：

- 同时只运行一个节点和一套 TUN 会话；没有命中规则的流量默认代理，不可用时不暗中改成直连。
- 支持域名、IP/CIDR 自定义代理/直连，以及可选的社区站点集合；自定义规则优先于站点集合。
- 保存节点或分流不自动打断运行；明确执行“应用并重启”后生效。当前实际出口与下次选择分别呈现。
- 新安装不自动连接；保留核心自动准备、独立应用更新、托盘、登录自启和一次运行恢复。
- 配置、节点凭据、日志保存在本机。外部核心保持用户所有，更新器不覆盖。

本次允许重构 CoreService、运行会话、存储模型、IPC 和对应前端。保留 Tauri 2 / Rust、TypeScript 原生 DOM / Vite、标准 GitHub Actions / Tauri 打包。

不扩展为策略组系统、订阅转换服务、通用配置编辑器、网络管理框架或常驻系统服务。订阅 URL、后台刷新、测速排行、自动换节点、按进程分流、阻断规则、正则表达式和任意远程规则源不进入首版。导入的本地节点批次只记录来源标签，不预建订阅生命周期。

这次需求明确扩大了原有 AGENTS 的节点与 TUN 边界；后续实施同步正式约定，不用旧限制否定新需求，也不提前把计划写成已实现能力。

## 3. 先修正功能方案中的几个实现假设

1. **启动成功不等于节点连通。** “TUN 运行中”要求进程、接口和预期路由成立；远端连接是否正常另列诊断结果，不用一次站点请求定义所有网络成功。
2. **DNS 不能笼统地说按同样规则自动工作。** 必须定义节点地址解析、直连/代理解析、IP 分流和 IPv6 的先后关系，见第 9 节。
3. **规则必须完全确定顺序。** 不采用笼统的“精确优先”：域名和 IP 同时命中、站点集合重叠也要有结果，见第 8 节。
4. **导入不能静默丢参数。** 识别协议名称不等于兼容所有 TLS、传输和依赖组合。未知字段和被引用的其他 outbound 不能直接丢弃。
5. **运行文件不能停止就全部删除。** 应用失败恢复和启动恢复需要最后成功输入；仅删除不再引用的临时文件，最多保留当前、候选和一个成功基线。
6. **TUN 清理不能恢复整张旧路由表。** 只处理本会话创建/修改且仍可核对所有权的资源，不能覆盖用户中途切 Wi-Fi 或其他 VPN 的变化。

## 4. 最终职责划分

运行链路：`页面/托盘/启动恢复 → SessionService → 固定运行计划 → 本地或授权会话 → sing-box`。

| 模块 | 唯一职责 | 不承担 |
| --- | --- | --- |
| `core/`，继续使用 CoreService | 外部/受管二进制选择、准备、采用、版本证据、一次核心版本回退 | 节点 CRUD、运行意图、TUN 权限、页面状态 |
| 新增 `profile/` | 节点模型、受限格式导入、分流模型、规范化和配置生成 | 启停进程、下载核心、重复实现 sing-box 的路由匹配器 |
| 新增 `rulesets.rs` | 固定站点目录、不可变规则资产、缓存与候选更新 | 通用订阅源、任意规则平台、直接修改当前运行 |
| 新增 `session/`，SessionService | 运行计划、启动/停止/应用、恢复意图、失败恢复、统一快照 | 自建网络转发器、通用工作流引擎 |
| `runtime.rs` | 普通子进程和检查进程、日志管线、真实退出 | 用户选择和设置提交、路由策略 |
| `platform/` | 原生进程、授权启动、接口/路由观测、限定范围的资源恢复 | 产品决策、节点解析 |
| `settings.rs` | 唯一持久化写入者、迁移与修订检查 | 后台自动启动或联网 |
| `lifecycle.rs` | 退出预检、封闭接纳、等待所有者、统一收尾与安装交接 | 自行选择节点或绕过 SessionService 结束进程 |

`profile/` 初始只需要 `mod.rs`、`import.rs`、`config.rs`；`session/` 初始只需要 `mod.rs` 和授权会话协议文件。`platform.rs` 因新增三平台能力迁为目录，现有 Job/进程组实现原样迁入，再做相关行为修改。按职责拆分，不为每个名词创建 trait、仓储或服务类。

不新增总线、依赖注入容器、通用任务调度、插件适配器或第二套存储。只使用两种具体执行方式：原始配置的本地进程、生成配置的授权 TUN 会话；不建立可无限扩展的后端注册体系。

迁移后删除 CoreService 中原有的运行意图和启停实现，所有生产入口转向 SessionService。不长期留下“新入口调用旧逻辑、旧入口继续可用”的双路实现。

### 4.1 服务协作与启动准备，避免换个地方继续耦合

CoreService 只向会话提供固定二进制引用、已准备候选及核对/提交采用结果；它不反向持有 SessionService。SessionService 固定一次运行输入，生成兼容配置，核对候选并协调采用。复用同一个被接纳的会话操作票据，不让两个服务依次调用彼此的公开入口、重复获取冲突票据。

`ManagedCore` 下载完成只发布 PreparedCore，不自行启动、改配置或切版本。Application 后台唤醒交给 SessionService 做一次协调：首次缺核心时，即使还没有节点也可核对并提交核心就绪；无节点只阻止连接，不阻止安装核心。已有活动会话时只保留候选；停止后/下次启动的采用由同一协调入口处理。

生成配置兼容结论绑定有效输入指纹与核心证据。核心版本、规则资产、所选节点参数改变后不能复用旧结论。配置生成/校验针对固定输入，过程中用户新保存的设置保持待应用，不偷换本次计划。

当前 `UpdateService` 持有 RuntimeService 只用于两处日志写入，整改为传入已有 `Logs` 的克隆，删除运行服务字段与相应构造参数；应用安装前停止仍由 lifecycle 协调 SessionService。`ManagedCore` 仍需要核心版本/配置检查能力，保留所需命令执行资源，不与应用更新一起机械替换。不增加 SessionService 包装去掩盖旧依赖。

## 5. 存储：单写入者，期望配置与真实运行分开

建议升级为 schema 4，沿用一个 `settings.json`：

| 数据 | 内容与边界 |
| --- | --- |
| 核心上下文 | 保留 `coreSource`、`managed`、`coreRevision`；修订只覆盖二进制来源、采用与 trial |
| 连接配置 | 新 `profileRevision`、运行模式、节点列表、当前选择、分流；语义变更统一提交 |
| 原始配置 | 显式 `externalConfig` 分支，保存原 `configPath/pendingConfigPath`；不与生成配置字段拼接 |
| 更新偏好 | 继续 `preferencesRevision`；不会被节点编辑和核心更新覆盖 |
| 恢复设置 | 保留开关与成功运行意图，新增最多一份最后成功运行输入；不保存“当前正在运行”的假事实 |
| 桌面设置 | 沿用现有首次收起记录；登录项仍读取系统事实，不复制到此文件 |

节点使用内部稳定 ID。协议设置是受支持的类型枚举及字段，不是可以任意嵌入 JSON 的 `protocolOptions`。规范化后用于去重的凭据摘要仅在 Rust 内部使用，不作为公开节点 ID。

保存连接配置时检查 `expectedProfileRevision`，基于最新存储合并对应字段，成功落盘后再发布新状态。节点和规则处于同一写入事务，不另设数据库、凭据库和配置库之间的提交协议。

“待应用”比较当前选择、该节点的实际参数、路由/DNS 策略和规则资产的有效内容指纹；节点重命名、修改未运行节点、下载但未采用的核心不使当前连接错误地显示待应用。普通前端只收到待应用布尔值及安全摘要。

运行开始时固定 `RunPlan`：会话 ID、意图代次、模式、有效输入指纹、核心版本/摘要、配置摘要、规则资产引用及工作目录。运行中不随节点列表或后台缓存变化。

最后成功输入保存所用节点参数、分流和固定资产引用，用于回退和一次启动恢复。它不是第二套用户可编辑配置。删除被最后成功输入引用的节点时清除该恢复依据及运行意图；运行中的节点不能直接删除。凭据更改、模式切换等使恢复依据不再适用时明确失效，不能暗中运行已删除/替换的凭据。

权限：含凭据的存储、迁移备份、运行文件和临时文件都限制为所属用户/必要授权进程可读。Unix 使用私有目录和 0600 文件，Windows 显式检查并设置相应 ACL。现有 `write_json` 只有写临时文件、同步和 rename，应将所需私有权限覆盖到这条具体写入链，不能只给最终文件改权限。

不在本轮引入跨平台密码保险箱或声称凭据已加密；页面默认遮盖敏感字段，不提供无需求的明文导出。

## 6. 旧数据与原始配置兼容

- schema 0/1/2 继续通过明确旧结构迁移，再进入 schema 4；schema 3 单独迁移。保留原始字节备份，不覆盖已有备份；不为一次升级制造每层中间文件。
- 已有有效或待校验外部配置：保持原始配置模式、原路径、相对资源工作目录和原恢复意图。不得根据 JSON 猜节点并自动启用 TUN。
- 没有旧配置的新安装：默认生成配置模式、默认代理、无节点、未连接；LAN 基础直连启用，站点集合初始均不启用。
- 原始配置模式只负责既有运行和校验；页面明确“网络行为由此配置决定”，不能显示为已经提供受控 TUN。两个模式不混合，切换要求会话已完全停止。
- 外部核心选择始终保留。生成 TUN 首版只允许有来源证据的官方受管核心进入授权会话；用户需主动切回应用管理，不能升级后自动接管外部核心。
- 外部核心执行完整原始配置继续沿用普通权限；不提供“把任意外部核心自动提权”的新功能。
- 损坏设置、未知 schema、未知未来字段保留原件并阻止覆盖；不自动联网、迁移丢字段或默认启动。
- 老版本不认识 schema 4；降级只能在停止后手工恢复备份，不能让旧版本直接覆写新格式。明确记录升级/降级边界。

原有 `pendingConfigPath` 只在原始配置分支保留；生成模式不借用它存放应用生成文件。

## 7. 节点导入：可解释、可取消、一次提交

### 7.1 支持范围

首版接收多行分享链接、TXT，以及 sing-box JSON/JSONC 中独立的代理 outbound。协议目标为 Shadowsocks、Trojan、VLESS、VMess、Hysteria2、TUIC，但每种仅承诺有解析夹具和真实核心校验的标准变体；支持矩阵列明 TLS、Reality、TCP/WebSocket/gRPC、SS 插件等组合。未支持组合明确拒绝，不标成“部分支持”后丢参数。

完整配置仅提取独立节点，不采用 inbound、route、DNS、实验 API 或文件日志。selector/urltest/detour 依赖链、外部证书/私钥文件、未知字段和需额外资源的节点逐项报告不兼容。已可识别的 TLS/传输字段必须完整保留。局部失败不能连带导入未验证参数。

JSON 使用现有 serde_json；JSONC 优先调用已选核心的格式化命令读取其规范输出，必须在预研验证命令不会改写原文件。若固定支持版本不能安全输出，则将 JSONC 节点提取明确延后，不手写去注释器；原始 JSONC 运行功能照常保留。核心未就绪时不承诺完成依赖核心的提取/语义校验。

### 7.2 导入链路

`受限输入 → 解析/规范化 → 提交前校验 → 去重 → 预览 → 用户提交 → profileRevision 检查 → 单次写入`。

- 初始限额：单次输入不超过 2 MiB、单链接 16 KiB、单批 500 个节点；文件读取和解码按限额进行，超限明确反馈，不能先无限读入再检查。
- 地址、端口、UUID、URL 编码、Base64、IPv6 authority 和支持字段由 Rust 校验；应用校验输入结构，最终协议配置由 sing-box 检查。
- 返回逐条成功/重复/不兼容摘要与输入行号；错误不回显密码或完整分享链接。导入前不自动运行节点或做外网测速。
- 预览结果和待提交节点保留在后端短期票据中；前端拿到无凭据摘要和票据。取消/退出/提交完成即释放，不建立持久任务队列。
- 提交只接收有效票据、选中项和预期修订；预览期间节点列表变化时重新去重并返回可解释冲突，不重复创建。
- 去重按规范化后的完整连接参数，忽略显示名；不按地址端口误合并不同账号。首版重复项保留原记录，不增加“导入时自动改名”分支。
- 节点未选中时允许增删改；正在运行的节点参数不可直接覆盖，可另存为新节点。选择其他节点只改变下次运行输入。

不新增生产依赖是默认约束。分享链接需要 Base64 时优先提出将 Cargo.lock 已存在的 `base64` 直接声明并固定版本，避免自写解码器；这仍属于新增直接依赖，实施前单列说明。地址规范化复用 `reqwest::Url`，CIDR 使用标准 IP 类型与受测前缀计算；不为整套协议引入转换服务或大型解析框架。

## 8. 分流顺序与规则资产

### 8.1 唯一、确定的优先级

生成配置采用以下顺序，无拖拽排序：

| 顺序 | 行为 |
| --- | --- |
| 1 | 本机、链路本地、TUN 自身和节点传输的防回环处理；LAN 私网固定直连 |
| 2 | 自定义域名：精确匹配优先，再按后缀从长到短；域名可识别时先于自定义 IP |
| 3 | 自定义目标 IP/CIDR：按最长前缀优先，IPv4/IPv6 分别规范化 |
| 4 | 已启用的站点集合：直连集合在前，代理集合在后；集合内无人工排序 |
| 5 | 未命中流量按用户默认策略，初始为代理 |

相同规范化规则不可保存两个相反动作。父域与子域、宽网段与窄网段允许相反动作，按上述具体程度决定。对 LAN 基础规则的反向覆盖首版拒绝并明确原因，不保存永远无法生效的代理规则。

域名已知且自定义域名与自定义 IP 冲突时，域名胜出；只有 IP 时只能进行 IP/集合匹配。两个站点集合有重叠时直连胜出，用户可通过自定义域名覆盖。该规则写入页面帮助和验收，不宣称应用能自动发现所有第三方集合的内部交集。

域名输入接受主机名，提供“仅此域名/包含子域名”；规范化大小写、尾点与国际域名。不把 URL 路径、正则、模糊关键字当作域名。IP 仅接受目标地址或 CIDR，网段统一为网络地址；核心负责实际路由语义。

### 8.2 固定站点目录

使用 [sing-geosite](https://github.com/SagerNet/sing-geosite) 的 sing-box 规则集作为一个固定来源。首版维护少量站点 ID、中文显示名、上游文件映射、许可说明和版本；GitHub、Google、YouTube、Telegram、Microsoft、Apple、OpenAI、国内站点等须在预研确认真实集合及内容覆盖，不凭站点名拼下载地址。国家 GeoIP 规则包暂不引入，自定义 IP/CIDR 已满足首版 IP 分流。

随应用包附带首版目录对应的有效规则集和固定摘要，保证已有核心与节点时首次启动不必等待 GitHub。包大小与许可在 P0 核对；不把“无法下载默认规则”留成首次联网的循环依赖。

用户按站点选择代理、直连或不启用；同一集合只能一个动作。每次生成只引用已启用集合。不开放任意 URL、本地 SRS、第三方脚本或多格式转换。

规则更新默认手动，首版不另建周期调度。按固定上游提交获取，独立验证内容、大小与核心可读取性后作为候选：

- 从可信上游确认提交与对象，不把下载字节自己算出的摘要当成来源证明；没有上游签名时如实记录 HTTPS/固定提交的信任范围。
- 下载/更新只产生不可变版本文件，不原地覆盖正在引用的规则集；变更后显示“规则更新待应用”。
- 当前和最后成功会话引用的版本保留；其他未引用缓存可以清理，不能删除成功恢复依赖。
- 下载失败继续使用当前有效版本。若用户新增集合在本地无有效文件，则阻止该候选应用，保留当前会话；不能悄悄忽略集合后启动。
- 源不可达、超限或解析失败是规则更新错误，不能触发重下核心或自动换节点。

现有 `updates/network.rs` 的 Transport 带 GitHub URL、线路健康、API 凭据规则，可供固定站点资产使用；先复用现有类型。仅出现真正重复代码时提取具体 HTTP/限额函数，不把本主题扩成通用下载框架。规则资产不用 `Component` 新增一个“可安装组件”，也不与应用重启更新混为一体。

## 9. 配置生成、DNS、IPv6 与启动循环依赖

配置生成是确定性的纯转换：`固定连接输入 + 核心能力档 + 固定规则资产 → JSON + 摘要`。只生成一套 TUN、direct、选中代理、固定 DNS 与路由；不开放管理 API、任意监听、日志文件路径和脚本执行入口。

核心能力档按实际验证版本范围选择少量模板，明确最低支持版本，不持续堆积每个版本字段补丁。新核心先校验当前配置，回退核心重新使用兼容模板生成；不支持的版本保留原始配置模式或阻止生成模式启动。

DNS 必须完成以下闭环：

- 启动前获取物理网络和原解析入口，用该网络解析节点服务器地址；不能先把节点主机名请求送入尚未建立的节点。
- 直连域名使用直连解析通道；代理域名和未匹配域名默认使用经当前节点的解析通道。远端加密解析端点使用明确的启动解析，避免自引用。
- IP/CIDR 判断需要真实目标 IP 时，由 sing-box 在适当阶段解析后继续路由；不能只有域名规则生效、IP 规则实际永远命不中。
- 首版不使用 FakeIP、不增加 DNS 编辑器；固定受测的解析方案，避免把解析器选择变成第二套产品。
- 标准系统 DNS 进入 TUN 受控处理；应用自带加密 DNS、ECH 或只有目标 IP 的流量未必能获取域名。不能承诺所有 HTTPS 流量都可恢复域名，无法识别时使用 IP 规则和默认策略。
- IPv4/IPv6、TCP/UDP 都需有明确转发和解析行为；IPv6 不支持时应阻止承诺完整 TUN 或明确受限模式，不能让它绕过默认代理，也不通过全局禁用系统 IPv6 解决。
- LAN、节点传输与自身流量的排除仅保证必要防回环，不把所有 Sing Shell 下载都宣称为可绕过故障节点。

选中节点失效时，代理目的地连接失败；已有明确直连规则仍可直连。首版不做持续系统断网锁，异常退出清理后系统会恢复原网络，必须明确“运行期间不静默降级”与“停止后恢复网络”这两个行为。

核心和规则后台更新均不处在每次启动必经的联网路径；有本地有效材料即启动。首次核心/受信任授权副本缺失等必要准备可以等待一次，失败结束本次请求，不无限等待后台后来成功。

## 10. 授权与 TUN 会话：先验证平台，再接产品入口

### 10.1 确定的产品与安全边界

普通权限 UI + 按需授权的独立网络会话进程。该进程只管理本次 TUN，不持有登录项，不承载 WebView；UI、应用更新和用户设置写入不整体提权。Windows/Linux 不创建常驻服务；用户已明确允许 macOS 13+ 使用 Apple SMAppService 注册受限 helper，只在连接时运行、断开后释放网络、不做崩溃重连。更旧 macOS 保留原始配置运行，不提供受控 TUN。

授权进程由同一 Rust 工程构建和随包签名，使用专用启动入口或二进制，在构建原生 UI、读取 UI 设置和取得 UI 数据锁之前分派。它拥有实际 sing-box 进程与本次网络资源，控制端只能请求固定的开始/停止/查询，不接受 Shell、任意程序路径或任意原始配置。

授权成功后保持本次应用会话的控制通道，使正常换节点重启可复用授权；TUN 停止后处于无网络资源的受限待机。退出、更新交接、父进程消失或认证控制通道断开时清理并结束；不跨应用重启存活，不定时重连。

协议必须有版本、随机会话标识、操作代次、消息上限、对等身份与控制端生命周期核对。Windows 受限命名管道，Unix 私有 socket/对等凭据；提权后的 root 身份不能沿用普通同 UID 激活协议。控制信道不得与现有“唤回窗口”的实例激活端点共用。

### 10.2 高权限资产信任

现有 `ManagedRef.hash/source` 和缓存都在用户可写目录，适用于普通用户态完整性核对，不能直接充当高权限执行的信任根。

授权进程只执行自己验证并固化到受保护会话/核心目录的官方核心：首次独立向固定官方 HTTPS 上游确认发行身份/摘要，核对归档、原生架构和解包结果，再保留受保护的已验证副本。后续离线运行使用该副本；UI 提供的本地 hash、路径、环境变量或镜像响应不能批准新的高权限程序。不能独立确认来源则停止并报错，不退回执行外部路径。

运行配置由授权进程根据受限类型输入重新生成，文件、规则资产复制到私有目录后核对，使用固定绝对路径与受控工作目录；拒绝符号链接/重解析逃逸和检查后被替换的用户文件。子进程环境只传必需值，不继承 GitHub token、任意代理环境或动态库注入变量。授权副本不改变用户已选外部核心，不构造另一套自动更新器。

首次安装准备授权副本可能需要一次额外可信上游访问；不能谎称普通缓存已足以支持首次离线提权。核心下载镜像可供传输字节，但不能供信任证据。

### 10.3 原生可行性是 P0 交付门槛

| 平台 | 预研方向与必须验证的事实 |
| --- | --- |
| Windows x86_64/ARM64 | 原生 UAC 授权启动网络进程，获取真实句柄/身份，验证 Job/父进程退出清理；核对官方核心所需 TUN 驱动/DLL 的原生架构、许可、受保护搜索路径与实际包分发，不能只解包 EXE 就宣布具备 TUN |
| Linux x86_64/ARM64 | 系统授权器（如 pkexec/polkit）启动受限进程，验证 DEB/AppImage 真实入口、策略文件、/dev/net/tun、权限及网络命名空间；缺少授权组件明确报不支持，不提示在终端运行整套 root GUI |
| macOS ARM64 | 在既定最低系统范围验证系统认可的授权启动、签名包布局、utun/路由/DNS 生命周期和控制端身份；不能把废弃授权接口、`sudo` 管道或拼接 AppleScript Shell 命令当作默认落地方案 |

macOS 的范围决策已根据 Apple 文档和用户明确授权收敛为上述受限 SMAppService helper。P0 仍须验证签名包身份、注册/允许状态和实际会话生命周期，不能把头文件可编译等同授权路径可运行；不使用整套 GUI 提权替代它。

P0 输出每平台真实原型、具体 API/授权工具、最低系统、包资源、必要直接依赖和清理证据；本计划不把尚未验证的平台启动器写成已经实现。Windows/Linux 能先证明链路，不能代替 macOS 或两种 ARM64 的原生结论。

## 11. 会话生命周期、取消与失败恢复

### 11.1 状态与所有权

会话只保留 `stopped / preparing / authorizing / starting / running / stopping / cleanupRequired` 等实际阶段；错误作为带阶段的字段，不为每个错误新增一个状态。后台核心维护和规则更新各有自己的状态，不覆盖正在运行的会话。

会话快照分别呈现实际核心 PID/版本、运行节点摘要、TUN 观测结果、应用中输入、待应用设置及动作能力。网络诊断另列 `unknown / reachable / failed`，不得用 PID 冒充代理出口可用。

授权进程持有同机 Sing Shell TUN 资源独占租约；普通应用的“同数据目录单实例锁”不足以防止两个不同数据目录或用户同时接管系统路由。冲突应拒绝并显示已有会话，不杀其他 VPN、不抢占其他用户的网络资源。

### 11.2 启动

1. 接纳一个会话操作，固定意图代次，核对无未清理会话与系统资源冲突。
2. 固定所选节点、规则版本和核心；完成必要本地准备及生成模式校验。
3. 申请/复用授权；拒绝、取消或超时即结束本次请求，迟到授权结果也必须释放。
4. 授权进程确认资产、生成私有配置，再执行 `sing-box check`；不信任 UI 的“已校验”。
5. 记录本会话必要的资源所有权，启动核心，核对 PID、TUN 接口、预期路由和 DNS 接管；启动阶段的有界观察沿用，但不能单靠 2 秒存活。
6. 收到真实成功后，在意图代次仍有效时提交成功输入、核心 trial 和恢复意图。持久化失败必须停止新会话并清理。
7. 发布 `running`；页面和托盘读取同一结果，不各自计时宣布成功。

### 11.3 保存与应用

- 保存只提交期望配置；正在运行的 RunPlan 保持不变。表单未保存与配置未应用分别提示。
- “应用并重启”先固定并校验候选，不中断旧会话；准备失败仍运行旧会话。
- 准备成功后才停止旧会话并确认清理，随后启动候选。这个用例固定核心版本，首版不在同一次用户换节点中顺便采用新核心，避免两类回退相乘。
- 候选启动失败且清理完整时，按“应用并重启”的产品合同，尝试恢复刚才成功会话一次；不切其他节点、不覆盖已保存的新设置。UI 显示“应用失败，已恢复旧节点；新设置未生效”。
- 旧会话恢复也失败则保持停止/需清理，保留两次原因。主动停止/退出取消剩余恢复，不允许迟到成功重新联网。
- 新保存设置与本次固定候选不同，只影响下一次应用；不能在停止窗口里偷换输入。

### 11.4 核心采用与回退

CoreService 负责候选与上一个核心记录，SessionService 负责将固定运行输入交给候选检查。配置兼容失败绑定“核心候选 + 有效输入指纹”，输入改变后允许重新检查，不能永久屏蔽合法版本。

保持运行中只准备核心，下次从停止启动时才采用。新核心在兼容检查或早期自身启动失败时，清理后最多回退上一核心一次，并重新生成适配配置。权限拒绝、缺驱动、站点文件缺失、路由冲突、用户取消、一般网络不通不能被当作核心版本故障。授权进程报告结构化阶段/原因，不能靠匹配日志文案判断回退。

普通后期异常退出不自动换核心或重启。一次核心回退与一次“应用失败恢复旧会话”分属不同用例，首版通过固定核心版本禁止嵌套重试树。

### 11.5 停止、异常与资源恢复

- 用户停止先撤销恢复意图与正在启动的代次，即使磁盘保存失败也继续停止；“实际停止结果”和“意图未保存风险”分开报告。
- 有界请求 sing-box 优雅关闭，等待接口/路由释放；平台不支持或超时才强制结束。强杀后的清理是必经过程，不能将 kill 成功等同网络恢复。
- 授权进程记录自己的 TUN、路由/DNS 改动及所有权；只撤销仍属于本会话的差异，保留用户和其他 VPN 的新变化。能由 sing-box 原生清理的交给核心，适配层验证并做必要补偿。
- 核心意外退出、UI 崩溃/控制通道丢失均触发同一清理；授权进程本身崩溃后只留下受保护恢复记录，不宣称断电/强杀下可瞬时恢复。下次启动在提权后先核对残留，再接纳新会话。
- 清理失败保留 `cleanupRequired`、真实进程/资源和重试入口，禁止第二会话及应用安装交接。不能无差别重置网络、删除其他接口或按旧 PID 杀掉被复用的新进程。
- 正常清理后释放不再引用的运行文件；当前和最后成功输入所需资产保留。临时授权进程不能被 Drop 的尽力而为替代。

### 11.6 一次运行恢复

恢复开关仍默认关闭；启用后恢复最后确认成功的运行输入，未应用的新设置不自动变成登录后接管网络的配置。若它与当前保存设置不同，显示正在运行的版本和待应用提示。

仅当本次必要核心/资产可用且恢复依据仍有效时尝试一次；后台启动不得反复唤起 UAC/授权框，没有可复用非交互授权就显示“等待手动授权”，不把它作为待重试任务常驻。手动启动可以明确完成授权。

停止、关闭恢复、模式切换、删除恢复节点和退出撤销请求；失败后后续下载完成不得复活。运行中的正常关闭/更新保留成功意图，主动停止撤销。继续沿用现有意图代次和一次消费语义。

## 12. Admission、锁与退出交接

保留现有 Admission/Operation 机制，只增加与真实资源对应的连接配置提交、规则准备和会话操作分类，命名按最终职责统一。

| 操作 | 并发合同 |
| --- | --- |
| 启动/应用/切换运行模式 | 同一会话互斥；固定输入后允许独立表单继续保存，但不能改变本次计划 |
| 停止/退出 | 停止可取消正在准备/授权/启动的所有者，等待它回收真实资源；退出再封闭所有新接纳 |
| 节点导入/分流保存 | 与实际网络运行并行；提交时修订检查；同次写入仍由 SettingsStore 串行化 |
| 核心下载/规则更新 | 可与运行并行；只生成不可变候选；不持有运行锁等网络 |
| 核心采用 | 与启动准备串行，绑定核心和配置有效指纹；运行中不切换 |
| 原生登录项 | 沿用独立操作票据；退出等待真实系统写入，不因前端隐藏就认为结束 |

不跨网络等待、授权框或用户编辑持有 SettingsStore 锁。操作取消信号只是请求；任务持有者完成进程/IPC/临时文件收尾后才释放票据。采纳提交时再次核对代次、模式、核心上下文及关闭状态，拒绝迟到回调。

退出/更新固定顺序：

`所有页面草稿决定 → 封闭接纳并撤销恢复 → 取消/等待导入、下载、授权、登录项操作 → 验应用包 → SessionService 内部停止及网络清理 → 结束授权进程 → 更新器交接或退出`。

`lifecycle::finish` 不再调用底层 `runtime.stop()`；托盘、设置退出、Cmd+Q、系统请求和应用重启均走这一入口。安装器可能直接终止应用，所以必要网络恢复不能位于 install 返回后。

安装失败时恢复可见窗口和可操作状态，已经停止的网络保持停止，不自动重新联网。旧授权进程不得携带到新版本；重启来源参数、授权会话 token 和旧控制端标识不向新进程传播。

## 13. IPC、前端与草稿边界

后端提供具体用例，不提供任意配置写入或任意文件/命令接口：

- 节点导入预览/提交/取消、重命名/删除、选择节点。
- 分流读取/保存、站点目录读取、固定规则更新。
- 会话快照、启动/停止/应用、重试清理、原始配置选择。
- 原有核心维护、应用更新、登录项与桌面操作。

长操作沿用 Receipt/operationId，并让快照携带对应操作结果、阶段、可重试原因和安全摘要。不能让文件框 IPC 返回就表示导入完成。前端不能伪造 restore/system 来源、已授权或任意路径的管理员执行。

`core_snapshot` 不能继续原样序列化新增含凭据的 Settings。拆出无敏感信息的状态 DTO：运行快照定期读取；节点摘要和规则编辑数据在进入页面/修改完成后读取；日志保持有界，继续使用 textContent。不为了少量数据预建实时同步框架。

前端按运行、节点、分流、设置四个页面组织，设置为低频入口。保持现有配色和 DOM 技术，不借机重做视觉系统或引入状态管理框架：

- `main.ts` 只装配页面、导航和单一刷新调度；`element` 等 DOM 小工具从 runtime.ts 移入独立 `dom.ts`，避免所有页面依赖运行页面。
- `core.ts` 收缩为明确类型与 IPC；节点、分流和会话 DTO 按使用处拆分，组件更新 UI 不接触凭据对象。
- 新增节点页与分流页；运行页展示实际节点、TUN、待应用和主要动作，日志可折叠，不再把核心来源和配置文件当主操作。
- 轮询仅更新非编辑状态。表单保留原 baseline/expectedRevision，服务端变化显示提示，不覆盖输入、焦点、选择或滚动。
- `updates.mayLeave` 只负责更新网络表单；新增一个很小的草稿协调函数汇集节点导入/分流/更新网络的具体未保存状态，供页面离开和真正退出使用。所有面板由应用根节点统一冻结，不再写死两个 ID。
- “保存但未应用”不弹丢弃草稿框；窗口收起保留草稿和实际会话。确认退出中的重复点击、页面重载和旧文档回执继续按现有 Coordinator 处理。
- 托盘不增加长节点列表，只显示实际节点、启停和打开节点/分流页面；跟页面共用 SessionService 的状态与动作能力。

应用错误不再统一覆盖 `runtime.error`：导入、配置、规则更新、权限、会话、核心维护、应用更新分别归属对应入口。后台规则失败不得让正常 TUN 显示停止。

具体调用者需要同步收口：

| 文件组 | 必须同时到达的改动 |
| --- | --- |
| `main.rs`、`lib.rs`、`app.rs` | 注册新模块/用例；原 `core_action` 与恢复设置转入会话；bootstrap、后台唤醒及隔离验收不能调用旧启停 |
| `desktop.rs`、`lifecycle.rs`、`startup.rs` | 托盘/系统入口共用会话；退出等待授权与网络收尾；重启参数不得携带会话身份；普通窗口激活端点保持用途单一 |
| `core/mod.rs`、`core/managed.rs`、`core/package.rs` | 移除配置路径与运行意图耦合；来源/版本试用规则与不可变资产核对保留；清理不能删除运行或成功恢复引用 |
| `src/core.ts`、`runtime.ts`、`core-model.ts`、`core-status.ts` | 拆开核心维护与会话 DTO/状态；去除 `configPath` 决定所有模式可启动的假设；按钮能力由后端给出 |
| `main.ts`、`desktop.ts`、`startup-settings.ts`、`updates.ts`、`index.html` | 四页导航、统一冻结/草稿、恢复语义与更新说明；DOM ID、禁用/忙状态、错误定位和返回入口完整配套 |
| `tests/support`、`lifecycle`、`managed_core`、`startup_restore`、`real_core` 及夹具 | 测试服务装配跟随新所有权；保留既有原始配置回归，新增授权/会话故障夹具，不能只让新测试绕开旧断言 |
| `smoke.mjs`、`verify-package.mjs`、`upgrade-fixture`、构建/验包流程 | 区分模式/schema；验证实际授权入口与包资源；真实应用退出/安装链路贯穿，夹具成功不得冒充生产链路成功 |

最终以所有启停、`runtime.stop`、恢复字段写入和配置路径读取的调用搜索做完整性核对：生产高层只通过 SessionService；底层进程自身清理和受控测试的直接调用分别说明，不以清空搜索结果为目标。

## 14. 数据和诊断保护

生成配置和节点凭据不放入快照、操作回执、错误对象、控制台调试和工程 smoke 报告。分享链接、带用户信息的 URL、token 和已知凭据在日志入口屏蔽；避免整份配置进入 stderr 的转发结果。

保留当前核心 stdout/stderr 的有界文本诊断。对于未知格式的核心输出，不能保证完全脱敏；界面和文档仍说明地址等可能敏感，首版不做自动上传、遥测或一键分享。敏感对象避免无约束 Debug 输出。

授权 IPC 只在本机且限制所属控制端，大小/时限均有界；不向公网监听。前端 Tauri capabilities 不扩展到 Shell、任意文件或通用管理员 API。

## 15. 实施顺序、退出条件与提交边界

| 阶段 | 代码与配套 | 阶段完成条件 |
| --- | --- | --- |
| P0：原生链路与依赖验证 | 五平台临时授权进程、真实官方核心、驱动/资源、DNS/IPv6/路由恢复原型；固定支持版本和导入矩阵 | 各平台给出可复现证据、包布局和 API 结论；macOS 授权范围冲突已解决；未通过不启动大规模节点 UI 实现 |
| P1：抽出统一会话边界 | SessionService 接管现有原始配置启停、确认、恢复；CoreService 留二进制维护；lifecycle/desktop/test support 全部改用同一入口 | 旧配置现有生命周期、回退、一次恢复、升级退出行为保持；生产调用者无旁路 |
| P2：存储与节点导入 | schema 4、私有文件权限、类型化节点、预览票据、一次提交、迁移；相应 IPC 与最小节点操作页面 | 无效导入不损坏旧数据；去重/取消/超限/修订冲突可解释；旧用户未自动转 TUN |
| P3：分流与确定性生成 | 明确优先级、固定目录/包内 SRS、DNS 模板、核心能力档、候选校验；分流页 | 生成配置通过真实核心检查；用实际路由验证域名/IP/站点冲突结果；离线材料完整 |
| P4：受控 TUN 运行 | P0 确定的授权启动器、资产信任、资源租约、真实观测、有界优雅停止和残留恢复；运行/托盘状态 | 启动取消、异常退出、UI 消失、恢复失败均不会留下未经记录的活动会话；所有清理失败可见且禁止重入 |
| P5：应用与全链路联调 | 候选准备后重启、一次旧会话恢复、一次核心回退、后台更新、草稿预检、启动恢复、真实安装交接 | 不形成重试树；修改未应用不误报；更新器启动前旧 TUN/授权进程均结束 |
| P6：实际包、证据与正式文档 | 五原生目标包测试、迁移/升级、授权/驱动/签名/卸载、功能文档 | 实际行为与合同一致；跳过项如实记录；必要平台支持未通过则不能宣布五平台完成 |

每阶段可拆为单主题提交，但同一个行为改动必须同时到达调用者、类型、测试、脚本和文档。结构迁移先保持行为，然后再引入新行为；不发布只改接口、资源没有所有者的半成品。构建各阶段可运行，但最终产品切换在完整链路通过后进行，不新增长期双实现 feature flag。

首版只允许本方案直接需要的依赖和构建资源。P0 必须列出必要平台绑定或小型解析库的具体用途、固定版本、锁文件与替代成本；本方案不授权顺带增加前端框架、数据库、插件权限或通用发布平台。

## 16. 验证矩阵

| 层次 | 必须验证 |
| --- | --- |
| 迁移/持久化 | 0/1/2/3→4、原字节备份、重复迁移、未知结构保留、写失败、私有权限；核心/连接/偏好修订互不覆盖；降级文档 |
| 导入 | 各支持协议真实变体、Base64/URL 编码/IPv6、未知字段不丢、依赖节点拒绝、JSONC 不改原件、批次去重、超限、取消与预览过期 |
| 路由配置 | 域名精确/子域、CIDR 最长匹配、域名与 IP 冲突、集合重叠、基础规则不可覆盖、默认代理无静默直连；顺序以真实 sing-box 转发观测验证 |
| 规则资产 | 包内摘要、固定提交、损坏/超限/源不可达、缺少必需集合、更新不改运行文件、旧版本被成功会话引用时不删除 |
| 会话并发 | 启动/停止/应用/退出竞争、授权迟到、规则/核心更新并行、提交失败、意图代次拒绝旧成功、机器级 TUN 租约、cleanupRequired 重入保护 |
| 权限安全 | 拒绝授权、错误对等端、重放/超长消息、任意核心/配置路径拒绝、用户目录替换、受保护核心证据、环境净化；普通 GUI 始终无额外权限 |
| TUN 实际转发 | 原生真实核心；TCP/UDP、IPv4/IPv6、直连/代理目的地、节点主机名解析、系统 DNS、LAN、切网/休眠恢复、其他 VPN 冲突 |
| 失败与清理 | 每个准备阶段失败、强杀核心、UI 消失/通道断开、授权进程异常、优雅超时、路由恢复失败、资源所有权检查；停止后真实网络恢复 |
| 核心兼容/回退 | 当前模板与核心版本、上一版本重新生成、候选只因兼容/核心故障回退、权限错误不回退、迟到取消不启动；应用失败恢复不嵌套核心回退 |
| 桌面/草稿/恢复 | 收起继续运行、无前端一次恢复、无交互授权不反复弹框、删除恢复节点、已保存未应用区别、表单不被轮询覆盖、旧退出回执无效 |
| 更新/安装 | 通过生产退出协调器执行应用更新；验包失败保留旧网络、交接前清理、重启不带旧会话 token、授权进程版本一致、驱动/DLL 与架构、卸载恢复 |
| 敏感数据 | 快照/错误/日志/脚本报告无节点密码、完整链接或私钥；文本渲染与日志上限不回归；配置临时文件权限和清理 |

单元/集成测试覆盖纯导入、规范化和生成，受控进程夹具覆盖取消/回退/失败时序。配置输出快照不能作为路由语义测试的替代品；不另写一份匹配器来验证自己生成的规则。

实际分流测试使用受控 DNS、代理服务器和直连/代理不同响应的目标验证出口，不依赖 Google/GitHub 当前可达性。普通 `npm run test` 不修改维护者网络；带权限的真实 TUN 测试独立在可丢弃原生机器执行，Linux 可辅助用网络命名空间，但不能代替 Windows/macOS。

阶段相关检查运行 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run build`；必要时先 `web:build` 定位前端问题。锁定工具链和 npm/Cargo 依赖。Windows/Linux 两个 ARM64 都用原生运行器，交叉构建不能代替验证。

扩展现有 smoke/verify-package，保留外部配置基线，再加入生成 TUN 专项。旧发行包按旧 schema 断言，新包按 schema 4 断言；不能统一改期望值后声称历史升级通过。`upgrade-fixture` 仅安装字节的结果不能代替真实运行会话 → 生产退出 → 安装 → 新版本恢复链路。

正式包必须验证 NSIS、DEB/AppImage、macOS app/DMG 中授权入口、签名/公证状态、驱动/资源位置、网络恢复与卸载边界。系统权限对话框、真实登录、睡眠切网和特定 Linux 桌面未实际执行的要列跳过，不以模拟快照冒充。
