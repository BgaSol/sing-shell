# 界面与操作链路整改计划

日期：2026-11-28。状态：实现已完成，本地检查通过，正在执行五原生与正式包验收；验收结束后删除本计划。

## 1. 目标与整改尺度

将 Sing Shell 收敛为沿用 SoDeck 多巴胺视觉、紧凑布局、统一控件和简洁流程的桌面客户端。整改范围覆盖界面、页面状态、编辑提交、相关 IPC 和业务用例；根据链路需要重构，不在旧行为上叠加样式与按钮补丁。

用户侧验收目标：

- 首次使用：导入入口 → 粘贴/选文件并自动预览 → 导入 → 连接，无配置向导。
- 连接/切换/断开是明确的单次动作；真实运行节点与下次选择分开。
- 规则表单一次保存；出口、启用和排序自动保存；连续编辑最后只需一次应用并重连。
- 设置只有常规、更新、高级；开关不跨页保存；低频诊断按需展开。
- 四页、弹窗和自绘顶部栏共享 SoDeck 色彩、描边、字体、控件和状态规则。
- 默认窗口内容紧凑，最小窗口与系统缩放下关键操作始终可达。

保留 Tauri 2 / Rust、TypeScript 原生 DOM / Vite、当前私有文件存储和后台循环。不新增生产依赖、前端框架、数据库、插件机制、通用任务/状态平台，不因界面整改重写网络执行层。

## 2. 已追踪链路与根因

以下为源码审查结论，未以本轮运行或截图代替原生验收。

| 链路 | 当前实现 | 应整改的问题 |
| --- | --- | --- |
| 全局界面 | `src/index.html`、`style.css`、`shell.ts` | 页面定义、全局连接区和设置 DOM 紧耦合；多层页头、说明和容器消耗空间 |
| 分流视觉 | `routing.css` | 页面与弹窗重新覆盖全局颜色、按钮、开关和选择器，形成第二套设计体系 |
| 前端状态 | `main.ts` → `app_snapshot/session_snapshot` | 轮询、导航、页面初始化、修订检查和草稿聚合混在入口；读请求合并后没有保证写后再次读取 |
| 分流保存 | `routing.ts` → `RoutingDraft` → `profile_set_routing` → `profile::Service::routing` → `SettingsStore::routing` | 弹窗只写页面草稿，整页另行提交；无效中间状态与退出处理依附整张表 |
| 下载与更新偏好 | `updates.ts` → `set_update_preferences` → `SettingsStore::preferences` | 应用检查开关、核心更新开关和下载网络共用一份草稿与整体替换，保存入口却在网络页 |
| 网络选项 | `connection-settings.ts` → `set_connection_options` | 只有一个开关也有独立草稿、保存、重新加载和退出预检 |
| 应用配置 | `core_action(Apply)` → `SessionService::apply_owned` | 已正确以实际运行节点和当前核心构造候选，应保留；不能改成连接当前选中的节点 |
| 连接待生效 | `SessionService::snapshot_for` → `ConnectionInput::fingerprint` | 已以有效输入与来源版本比较，应继续作为唯一判断，不能用前端 dirty 或修订数替代 |
| 运行模式 | `profile_mode` → `SessionService::mode` | 目前只允许停止后切换；模式和恢复意图分两次写入；简单前端“stop 然后 mode”无法保证中途失败边界 |
| 自动导入 | `nodes.ts` → preview/cancel/commit → `profile/service.rs` | 现在依赖手动预览；改成自动预览还会触及请求顺序、票据失效、JSONC 核心格式化及 Admission 互斥 |
| 编辑与退出 | `Modal`、各页 `mayLeave` → `desktop.ts` → `lifecycle.rs` | 弹窗退出只会丢弃/返回，多页另有保存决定；下载网络还有独立 dirty-dialog，难以兑现一次统一退出决定 |
| 窗口关闭 | Tauri `CloseRequested` → `Desktop::close_requested/hide` | 收起、托盘回退、首次说明已经存在，自绘关闭按钮必须接入同一路径 |
| 应用更新 | `UpdateService`、`CoreService` | 两个服务有不同职责；现有 `check_updates(None)` 实际只检查应用，不能通过改按钮文案假装两者都已检查 |
| 启动恢复 | `restore_tick` → `authorization::can_resume()` | 当前受控 TUN 不能后台恢复授权；常规开关不能给出自动联网承诺，原始配置一次恢复继续保留 |
| 活动与日志 | `activity.ts` → 独立分页 IPC → worker 采样 | 采样边界已有，应重组视图与读取时机；明细不可用不能被显示成零流量或网络断开 |

## 3. 必须保持的边界

### 3.1 状态所有权

- Rust 持有已保存设置、真实进程、运行输入、授权与系统资源；前端只能请求明确操作。
- 前端只持有当前页面、筛选、展开、尚未提交的编辑内容和短期请求状态。
- 选择节点、正在连接的目标、实际运行节点、最后成功连接记录继续独立。
- 核心维护、应用更新、规则内容版本、运行会话是不同事实。只在界面上协调展示，不合并为一个更新服务。
- IPC 返回 Receipt 表示接纳，不能立即显示连接、下载或清理成功；短事务成功返回才表示已持久化。

### 3.2 网络与数据安全

- 不重写 `session/tunnel/worker.rs` 的候选准备、一次恢复、TUN/DNS 释放与租约模型。
- 不改授权协议、不增加持久 helper，不接收任意管理员命令、核心路径或解析结果。
- `profile/config.rs`、`routing.rs`、`bypass.rs` 保持各自职责；sing-box 继续负责配置语义和实际路由匹配。
- 保存规则只做本地校验与写入，不解析域名、不提权、不启动连接。
- 保留启动前重新校验、失败保留有效设置、外部核心与原始配置不被覆盖的边界。
- 继续通过 `SettingsStore::write` 原子写入；不绕开修订检查，不让 WebView 拿到 NodeSpec、lastConnection、控制密钥或完整导入凭据。

## 4. 目标代码组织

在现有领域模块上调整，不做全仓目录搬家。文件名可随实现小幅调整，但职责不得混回页面入口。

| 模块 | 目标职责 | 处理方式 |
| --- | --- | --- |
| `src/main.ts` | 装配页面、启动状态读取、绑定原生事件 | 抽走轮询实现与设置页面细节 |
| `src/app-state.ts` | 唯一公开快照、修订采用与读取合并 | 一个小模块，不实现通用响应式 store |
| `src/api.ts`、`contracts.ts` | 现有 `core.ts` 的 IPC 调用与公开类型 | 按类型/调用拆两份，不再按每个命令生成包装层 |
| `src/shell.ts`、`desktop.ts` | 导航、连接呈现；原生窗口与退出协调 | 展示和原生生命周期分工 |
| `src/modal.ts` | 单一编辑会话、提交、关闭保护、焦点恢复 | 保留原生 dialog，不实现表单 DSL |
| `src/controls.ts` 与公共样式 | 少量重复的开关、分段选择、字段错误组件 | 只提取实际被多处使用的原生控件组合 |
| `src/nodes.ts`、导入编辑模块 | 节点列表与有界导入会话 | 从列表中分离会显著增加的预览逻辑 |
| `src/routing.ts`、规则编辑与来源模块 | 已保存规则表、单个编辑器、来源详情 | 用提交状态替代整页草稿 |
| `src/settings.ts`、偏好/更新编辑模块 | 分类、设置行、独立偏好保存、网络编辑器 | 分开更新展示与下载网络草稿 |
| `src/activity.ts` | 连接/日志视图、游标、滚动与可见性 | 后端采集协议复用 |
| `src-tauri/src/commands.rs` | 薄 IPC 适配、参数与公开结果 | 从 `main.rs` 搬出命令；不承接业务流程 |
| `profile/service.rs`、`profile/routing.rs` | 规则操作接纳、规范化与校验 | 有限业务操作，不引入通用 patch 引擎 |
| `settings.rs` | 当前状态上的原子修改、领域修订 | 加窄写入方法，保留单一文件与写锁 |
| `session/mod.rs` | 模式转换用例及既有连接入口 | 只抽取本次确需复用的内部步骤，不重写 SessionService |
| `desktop.rs`、小型平台窗口适配 | 自绘窗口能力与原生菜单 | 平台差异集中，不散入业务页 |

样式按全局 token、原生控件、应用布局、必要页内布局分层。只在结构复杂的页面保留页级 CSS；禁止页面重定义品牌 token 或复制整套按钮/输入样式。`style.css` 可作为明确的样式入口。

`main.rs` 保留启动装配、命令注册与原生事件。迁移命令时同步调整注册与工程测试；现有 smoke 装配若需要分离，做等价搬移，不趁机改写发行验收逻辑。

## 5. 前端状态、编辑与异步顺序

### 5.1 一个公开快照，按领域确认保存

保留“首次全量配置 + 轻量会话轮询 + 修订变化才读配置”的方案。事件只唤醒读取，不能成为唯一事实源；不改成每页轮询一份全量设置，也不新建事件总线。

读取协调器至少处理：

1. 同类读取最多一个在途；期间又收到写后刷新请求时，标记再读一轮，不能直接复用写之前开始的 Promise。
2. 配置响应按各领域修订采用，迟到读取不能覆盖刚确认的保存结果。显式备份初始化会清空前端基线并重新全量读取，不能用单调修订判断拦住重置后的合法低修订。
3. 页面编辑内容不被轮询重建；列表按稳定 ID 更新，保留焦点、展开和滚动。
4. 桌面退出请求、会话读取、更新读取的失败分别处理，维护服务的读取失败不阻止退出请求显示。
5. 隐藏窗口不读取活动列表与日志；会话与桌面轻量读取保留恢复需要。

更新和来源版本可以继续使用现有独立查询，不为减少 IPC 数量制造巨型全量快照。

### 5.2 不增加通用命令队列

- 分流控制器持有一个在途写 Promise；提交期间暂停该表的写操作，其他页面仍可浏览。
- 常规设置按实际设置行显示 saving；同一字段提交未结束时不能重复提交，不排队保存整份旧设置。
- 发起连接、切换或应用之前，等待本前端已接纳的分流/连接选项写入完成，再让后端冻结输入。失败不带着未知状态继续连接。
- 连接接纳以后产生的新保存可以正常成为下一次待生效修改，不追写已冻结候选。
- 不自动重放修订冲突，不后台重试无限队列。失败回到已确认状态，用户可以明确重试。

### 5.3 单一编辑会话

复杂编辑全部使用同一个 Modal：节点资料、导入、自定义规则和下载网络。页面不再各自持有长期整页草稿。

Modal 增加明确的提交回调、提交文案、dirty 判断与正在提交的 Promise。关闭/Esc 只处理当前编辑；退出可显示保存/放弃/取消；导入使用导入/放弃/取消。提交失败保持编辑器和焦点，不能清掉内容后再弹错误。

复用同一个 dialog 的决定区域，不叠加第二套顶层弹窗。异步等待直接等待任务 Promise，不使用多个 25/30ms 循环探测 busy。导航统一为可等待的请求；托盘导航处理完编辑决定后才确认请求已处理，避免先确认再丢掉导航。

### 5.4 退出前停止接纳新的界面写操作

退出预检先冻结页面、顶部连接按钮和应用菜单中会改变状态的入口，等待已接纳保存，再处理当前编辑会话。此时只允许预检拥有的保存/放弃/取消动作；取消退出后恢复交互。原生来源偏好等窄写入口同样必须经过 Admission 并检查 closing，不能直接绕过门禁调用 store。继续沿用 documentId/requestId 和后端关门、等待任务、释放网络的顺序，不新建第二个退出协调器。

## 6. 分流：从整页草稿改为原子业务操作

### 6.1 调用链

```text
规则行或编辑器
  → routing_change(expectedRoutingRevision, change)
  → ProfileService 接纳写操作
  → SettingsStore 在写锁下读取当前设置
  → 应用 change，统一规范化并校验完整候选
  → 同一次写入更新规则与来源偏好
  → 原子发布，递增 routingRevision
  → 返回已保存规则、修订及本次必要结果
  → 前端确认显示；Session 快照派生是否待生效
```

新增一个有限的 `RoutingChange` 类型：新增/保存自定义规则、批量添加固定来源、设置出口、设置启用、上/下移、设置默认出口、移除、恢复移除。参数表达意图，不接受 JSON 路径、任意脚本或泛型属性修改。

沿用整表完整校验和一次文件提交。操作级 API 解决旧整页提交的所有权问题，不放松后端验证，也不拆成多次写文件。

成功结果从本次 `SettingsStore::write` 返回的已提交状态构造，不能写完后再随意读取另一份可能已被后续操作改变的快照作为该操作回执。

### 6.2 校验与保存边界

- 新增/编辑规则直接提交正式候选，成功才关闭；不再先更新页面草稿。
- 代理出口清除绕过意图，切回直连不自动恢复。此联动由 Rust 统一执行，前端不做唯一保护。
- 绕过只在编辑器中设置；包含子域名等冲突在同一表单中修正，不允许列表留下无效待保存状态。
- 名称留空时，由规范化后的第一个有效目标生成受长度约束的名称；不根据非法输入预先写入名字。
- 域名批量粘贴只拆成编辑字段，不在 TypeScript 重写 Rust 的域名/IP/保护范围校验。
- 保存错误按规则 ID、字段类型和项索引定位。必要时为路由校验增加小型类型化错误；保留供现有调用者使用的文字格式，不解析后端字符串反推字段，不重做全项目错误框架。
- 保留 100 条策略、1,000 个自定义条件，以及现有绕过数量与地址边界。
- 原始配置、存储异常、退出期间在后端同样拒绝规则写操作，不能只将按钮置灰。

### 6.3 来源与撤销

新增固定来源默认出口在业务操作中统一决定：国内站点/中国大陆 IP 直连，其余代理。重复来源与批量添加上限在提交前整批验证，禁止部分写入。

删除返回公开的被删规则、位置和该来源的更新偏好。前端只保存最近一次删除结果；恢复使用当前修订，通过同一事务恢复规则与偏好，保留删除后其他规则的修改。无需持久化撤销历史或创建服务端撤销仓库。

恢复时重新检查重复 ID、来源与数量上限。删除后若来源已重新添加，不覆盖其新偏好；移除失败不生成撤销记录。来源目录和下载缓存继续由现有 RulesService 管理，前端撤销不承担文件恢复。

规则写入成功后再执行 `rules.reconcile()` 和必要的后台唤醒。来源偏好独立保存返回确认值，不被规则表重建成默认值。来源内容更新不递增 routingRevision。

### 6.4 删除旧实现

迁移完成后删除 `RoutingDraft` 的 baseline、整页 dirty、整页 save、跨页退出决定及相应控件；`routing-model.ts` 只保留必要的提交状态/纯呈现逻辑，若无独立职责则删除。

移除旧 `profile_set_routing`/`routing_validate` 的前端调用和无生产调用的 IPC 注册；仍被 Rust 集成夹具使用的整表测试入口按实际需要保留为内部能力，不让生产界面继续双路提交。

## 7. 设置：按用途保存，复用现有修订

### 7.1 更新偏好拆写

`UpdatePreferences` 的持久化结构可以保留。去掉前端整体替换它的入口，改成明确的应用/核心自动更新开关写入，以及独立下载网络保存。

- 开关只修改对应布尔值，在写锁内合并，保留其他开关和网络。携带该字段预期值以识别真正的同字段冲突；目标值已经满足时可以直接返回确认值。
- 下载网络保存使用已存在的 `network.revision` 比较；新 revision 由后端递增，不能由客户端指定。
- 上述成功写入仍递增 `preferencesRevision`，用于公开快照刷新。开关改变不递增 network.revision，避免无关修改让下载网络编辑冲突。
- 沿用 `Preferences::validated` 对 HTTPS、凭据、重复地址、数量等的验证。
- 只有网络内容变化才重置对应网络健康；核心自动更新偏好变化继续调用既有维护资格逻辑，不能把在途请求换成新的线路。

`network.revision` 当前已存在，因此无需新增 schema、数据库或一组为未来预留的修订字段。旧 schema 5 值按原值读取，不为 UI 整改要求重新初始化。

### 7.2 连接与启动选项

IPv4 兼容沿用 `set_connection_options` 与 connectionRevision，界面改为开关自动保存，删除单字段草稿和保存按钮。

登录启动继续读取系统事实，成功回执决定开关值；系统禁用/路径过期才显示修复动作。原始配置恢复继续使用 SessionService 的既有一次恢复；节点模式按授权能力说明需要手动连接，不以隐藏开关的方式偷偷改变已有持久化偏好。

恢复调度也按运行模式与 `can_resume` 门禁处理：节点模式不接纳当前平台无法执行的后台恢复，不把预期需要手动授权当成连接失败；原有恢复偏好和成功记录保留供实际支持的原始配置路径使用。不能只隐藏开关却让后端继续重复产生误导错误。

### 7.3 更新展示合并，服务不合并

一个“检查更新”按钮分别调用应用检查和受管核心 `maintain(Check)`，独立收集结果并显示各自状态。核心为外部来源时跳过维护并解释由用户管理；一项失败不吞掉另一项成功，也不把后台忙当成全局失败。

保留应用更新的下载、验证与重启安装链路，以及核心的准备、采用和一次回退。按钮根据实际阶段显示，不将“检查”改成隐式下载/采用，不因合并入口给当前网络制造重启。

下载网络集中到一个编辑弹窗，保存回调可被统一退出流程调用；诊断留在展开区域。删除更新开关与网络共用 draft、dirty-dialog、重复检查/下载入口和正常情况下常驻的重新载入动作。

## 8. 模式转换：在 SessionService 内完成

新增明确的模式转换用例，支持用户确认后的“断开并切换”，前端不串联两个独立 IPC 充当业务事务。

```text
确认目标与前置条件
  → 接纳一个排他的会话/选择操作
  → 失效等待恢复与迟到启动
  → 完成真实停止与网络清理
  → 再次核对目标、相关修订与核心资格
  → 原子提交模式及应清除的恢复意图
  → 返回成功；保持停止，由用户明确启动
```

实现要点：

- 已在连接/切换/停止中时不嵌套转换。复用 Admission 的现有所有者，不引入持久事务或编排框架。
- 内部抽出停止资源、提交模式等 owned 步骤；不能在已持有 Runtime/Selection 票据时再次调用会获取相同票据或取消自己的公开方法。
- 提前校对修订和目标能力，避免无效选择先断网；真正提交前再检查。停连接、持久化和程序准备无法形成一个跨系统原子事务，不承诺失败时完全恢复原运行状态。
- 停止/清理失败不提交新模式；设置提交失败保持旧的持久化模式与真实已停止状态，提示重试，不自动重启。
- 原始配置使用外部核心时，切回节点模式必须明确告知将采用官方受管核心。若材料未就绪，沿用现有准备/验证流程，资格确认前保留外部来源；不静默覆盖外部路径，不把节点模式先保存成无法运行的半成品。
- 模式、必要的核心来源变更和恢复意图在最终设置写入中一起校验提交；此前用户明确停止的意图按现有停止语义保存。准备过程不创建持久的“切换任务”。
- 文件选择框继续归宿主管理，取消不更换有效配置。启动前重新校验仍保留。

## 9. 自动预览与节点流程

保留 Rust 的 preview/cancel/commit 票据、10 分钟有效期、原子提交与去重。前端新增导入会话控制：

1. 输入一变立即使当前提交资格失效，按钮进入解析状态。
2. 短防抖后执行预览；同一弹窗最多一个解析在途，期间只记住最新输入，不为每个键入排队。
3. 当前解析结束后若输入已变化，丢弃结果并解析最新输入。关闭、换文件、重新打开由编辑会话 token 隔离。
4. 取消旧票据与开始新预览保持明确顺序，迟到 cleanup 不得取消新弹窗的预览。
5. 最新预览成功且有有效节点才允许导入；用户点击提交后冻结该输入和票据，直到事务完成。

自动预览调用频率提高后，检查 `Kind::Profile` 的现有互斥。建议只为预览/提交增加专用 `Import` 类型，保留单解析槽，不让慢 JSONC 格式化阻塞规则或节点资料保存；取消预览同时使票据失效并通知其可取消任务。提交继续在最终原子写入处保证不发布半成品。

JSONC 仍交由现有核心格式化，核心未就绪时说明这一文件需要等待，不能另引入解析器。当前批次出错不保留上一个可提交票据。规范化、协议限制、大小限制、凭据脱敏和临时材料清理全部沿用。

节点页按稳定 ID 更新，统一“连接/切换/使用中”，顶部统一断开；名称和标签编辑直接保存，删除保护继续后端执行。导入成功不自动连接。

## 10. 自绘外壳、样式与活动页

### 10.1 设计体系直接替换

以本机 SoDeck `packages/ui/themes.css` 的 dopamine token 和控件描边为来源，维护 Sing Shell 自己的小型固定主题，不依赖兄弟仓库运行时文件，不复制其工作台、插件或主题系统。

重新定义全局 token、控件类和应用布局，迁移所有真实调用点，随后删除旧样式。不得保留旧 `routing.css` 配色再写更高优先级覆盖，也不添加第二个末尾 override 文件或大量 `!important`。

`routing.css` 只维护规则列、目标输入和来源展开的布局。复选框、radio、文件输入等显式分类，避免当前通配输入选择器误把单选按钮套成文本框。原生控件保留正确语义与键盘行为。

### 10.2 标题栏贯通原生生命周期

- Windows/Linux 使用应用顶部栏；macOS 优先沿用 SoDeck 已采用的 overlay 思路保留原生交通灯。
- 平台窗口参数集中配置，避免各开发/发行配置不一致。只授予主窗口所需的最小窗口能力，不扩大成文件系统、shell 或全窗口控制权限。
- 关闭按钮调用正常窗口 close 请求，让既有 CloseRequested 拦截执行收起；退出菜单调用现有 lifecycle request。禁止前端直接 destroy/exit 绕过清理。
- 顶部真实状态和待生效入口由同一会话呈现函数生成；连接详情提供绕过地址刷新，不在分流页再造一个 apply。
- 最大化图标随真实窗口事件更新；拖动区与交互控件分开；页面、弹窗和错误区都以扣除顶部栏后的可用高度布局。
- Windows 最大化贴靠面板/系统菜单、macOS 缩放与全屏、Linux 窗口管理器行为必须实际验证。纯 HTML 最大化按钮不自动等价于系统非客户区按钮；若 Tauri 现有能力不够，只增加窗口边界内的小型平台适配，不引入另一套窗口框架。

标题栏原生能力先做窄范围可行性验证，确保问题被发现于外壳阶段，不能等页面全部重做后再发现无法拖动、贴靠或返回窗口。

### 10.3 活动与日志只重组呈现

连接/日志两个视图各自按需读取。采样不可用时统计显示不可用或短横线，未知速率不伪装为零。保留列表分页、行展开、会话隔离与后台采样边界。

日志只在日志视图且窗口可见时读取，用户上滚自动暂停跟随，必要时显示“回到最新”。继续限制 1,000 条，按文本展示，不添加日志数据库或系统旁路采集。

## 11. 分阶段交付与依赖

每阶段必须贯通调用方、IPC、存储/运行行为、测试、夹具和文档。阶段可拆多个单主题提交，不按“先堆接口、最后一起接 UI”交付。

| 顺序 | 完整交付主题 | 前置与完成标准 |
| --- | --- | --- |
| 1 | 公开状态读取与编辑交接 | 统一写后再读、迟到响应、导航和编辑会话；保持现有产品能力可用，补关键并发测试 |
| 2 | SoDeck 视觉、统一控件、紧凑外壳与自绘标题栏 | 使用阶段 1 状态；四页与弹窗统一样式，原生关闭/收起/退出与窗口行为可达；删除旧视觉覆盖 |
| 3 | 分流操作与一次保存 | 新原子业务操作、编辑器、来源、撤销、顶部待生效完整接通；删除整页草稿与双保存路径 |
| 4 | 设置归位与偏好分域保存 | 三分类设置、开关立即保存、独立网络表单、更新动作收敛；无跨页保存，旧 schema 5 保留 |
| 5 | 安全的断开并切换模式 | SessionService 用例、核心来源前置条件和失败边界接通；不改变 worker 协议 |
| 6 | 自动导入与节点操作简化 | 预览顺序/取消/提交全链路，节点资料编辑和真实连接状态一致；独立主题提交 |
| 7 | 活动双视图与整体收尾 | 活动/日志按需读取；删除失效代码与旧入口，完成最小窗口/缩放及五目标验证 |

跨阶段规则：已替换链路在同一阶段删掉旧入口，禁止长期保留双写、双草稿、双刷新器和功能开关。可共享少量实际使用的基础控件，禁止为后续阶段预建空层。

## 12. 测试与验收

### 12.1 必须补的行为回归

| 范围 | 应证明的行为 |
| --- | --- |
| 读取顺序 | 写前开始的读取晚返回不覆盖已确认保存；写中触发刷新后至少再读一次；重置后低修订可正常采用 |
| 原子分流 | 快速操作无丢失；冲突不覆盖；失败不改文件/内存；非法/批量来源不部分提交；保存不启动网络 |
| 撤销来源 | 恢复旧偏好与位置，保留其他修改；重复来源和上限拒绝；删除失败不产生撤销 |
| 偏好合并 | 自动检查开关不覆盖网络；网络保存不恢复旧开关；network.revision 仅由后端维护；在途下载继续原快照 |
| 连接应用 | A 正运行且已选 B，应用仍为 A；提交期间连接等保存；冻结后新保存继续待生效；准备失败仍运行 A |
| 模式转换 | 清理失败不切模式；保存失败真实已停止但旧模式保留；无迟到启动；外部核心不被覆盖；无票据自取消/死等 |
| 自动导入 | A 慢 B 快/连续输入只提交最新；关闭再开不串票据；新解析失败不能提交旧结果；过期/写失败/修订冲突保留正确资格与输入 |
| 编辑退出 | 无草稿直接退出；有草稿一次决定；保存失败留编辑器；收起保留草稿；旧 document/request 回执无效 |
| 真实状态 | PID 存在不等于 TUN 就绪；维护/采集错误不显示断网；来源内容版本改变与实际连接待生效保持一致 |
| 活动日志 | 不可用不显示假零；切会话丢弃迟到页；暂停跟随与详情焦点不被轮询破坏；恶意日志仅显示文本 |

Rust 回归优先扩展现有 `profile.rs`、`rules.rs`、`lifecycle.rs`、`startup_restore.rs` 与相关模块测试。前端并发逻辑沿用 Node 内置测试与现有 TypeScript 执行方式；淘汰 RoutingDraft 专属旧行为测试，但保留其保护的数据不丢失场景。

不编写只验证 CSS 字面值或复制实现的测试。公共控件与密度使用实际渲染检查，业务并发使用可控制完成顺序的 Promise/夹具。

### 12.2 夹具必须随调用链更新

- `scripts/ui-fixture.mjs` 实现新操作、保存失败、冲突、延迟与取消场景，保持仅用于隔离预览。
- `scripts/project.test.mjs` 的 IPC 注册扫描适配命令移出 main.rs 后的新注册位置；若移动了前端目录，扫描同步覆盖实际调用文件。
- 修改用到整表写入的 Rust 网络夹具，不能只更新浏览器模拟而保留实际包测试走旧入口。
- smoke 检查关闭按钮仍触发收起、草稿仍保留、真正退出仍等待清理，避免自绘外壳使原生检查失去意义。
- 保留现有源码/原包/签名/真实核心证据链，不将浏览器夹具成功计作 TUN 或平台通过。

### 12.3 执行范围

实施各阶段运行相关 `npm run check`、`npm run scripts:test`、`npm run test`；集成后完成 `npm run build`。样式调整检查默认 960×720、最小 620×560、长名称、空态、多项错误和系统缩放，检查键盘、焦点、读屏标签和减少动态效果。

正式交付验证使用现有 GitHub Actions 的五个原生目标：Windows x86_64/ARM64、Linux x86_64/ARM64、macOS Apple Silicon。ARM64 必须原生运行。自绘标题栏需要各系统实际窗口交互验证，单元测试或无头 smoke 不能证明系统贴靠与菜单交互通过。

正式发行仍需实际包启动/退出、官方核心集成、授权/取消、双栈转发、临时 DNS/TUN 清理、签名更新与设置保留；按实际执行记录失败、复跑和跳过，不把本计划视作发行授权或通过记录。

导航只在 `docs/README.md` 维护；不在 README 追加普通测试或版本流水。历史发行记录保留其当时事实，不改写成新方案。全部实施并迁入正式文档后删除本计划，不另建完成归档。

## 14. 主要风险与控制

1. **自动保存使写入更频繁。** 用单领域在途限制、原子事务和就近失败恢复处理，不引入防抖落盘导致退出丢数据，不将多次旧快照排队覆盖。
2. **系统窗口行为并不等同于 HTML 按钮。** 先验证标题栏最小原生能力，平台差异只落在窗口边界；必要的交互未执行就明确列为未验收。
3. **模式切换跨越设置和真实网络资源。** 明确停止优先和分阶段失败结果，保留原配置/来源；不建立自动重连或跨系统回滚承诺。
4. **高频预览可能触发慢核心格式化与旧票据竞争。** 单解析在途、最新输入、专用互斥与关闭取消一起落地，不只移除预览按钮。
5. **页面精简可能误删能力。** 使用前述能力清单和调用方搜索逐项核对，保留原始配置、外部核心、托盘、一次恢复、诊断和下载网络的按需入口。

本方案仅完成代码整改设计和源码链路审查；应用代码、实际界面与五平台包尚未执行整改或验收。
