# 节点模式 Fake-IP 与连接链路整改方案

状态：待实现。本文替代原 IPv4 兼容开关方案；已追踪本仓库代码及官方 sing-box v1.14.4 源码，未修改运行代码、设置或系统网络，也未执行本方案的核心实验和平台验收。

## 1. 要交付的结果

将节点模式的 DNS、域名还原、真实地址解析、分流和连接生命周期整理为一条完整链路：应用内置 Fake-IP，真实出口可选择 IPv4 兼容；普通用户继续选择节点、连接和编辑分流，无需认识假地址、DNS 服务器或缓存文件。

验收结果必须同时满足：

1. 普通代理域名经系统 DNS 获得 Fake-IP，进入 TUN 后由官方核心还原域名；真实拨号不会使用假地址。
2. 域名/IP/站点策略保持原有全局顺序、首次匹配和默认出口，IP 条件匹配真实解析结果，不能拿 Fake-IP 命中用户 IP 规则。
3. 开启 IPv4 兼容后，普通公网业务的真实目标连接使用 IPv4；节点入口解析仍独立。不能只改变浏览器看到的地址，或只改变代理服务器域名解析。
4. 保存不改变当前连接；应用、换节点、失败恢复和一次启动恢复都使用冻结输入，展示实际生效状态。
5. 正常重连和换节点可继续识别浏览器缓存的 Fake-IP；退出释放核心、TUN、临时 DNS 和 helper，不常驻后台服务。
6. 原始配置、外部核心、既有数据保护与五原生目标要求保持原合同。

Fake-IP 是业务域名入口机制，不认证节点 IPv6 能力，也不替代出口地址族策略。IPv4 兼容默认关闭；本次同时引入 Fake-IP，但不顺带把既有双栈出口改成仅 IPv4。

## 3. 范围和产品约定

### 3.1 用户只增加一个选择

在“设置 → 网络”的“连接兼容性”区块提供“IPv4 兼容模式”，默认关闭。Fake-IP 是节点模式内部实现，不提供 Fake-IP、真实 IP 两套可选配置，也不暴露地址池、TTL、DNS 上游或过滤列表。

勾选后点击“保存连接设置”；运行中提示“已保存，应用并重连后生效”，复用顶部原操作。未连接时下次正常连接采用。原始配置模式显示说明并禁用此项。连接设置与检查/下载网络分别保存，不互相提交草稿。

实际连接摘要只在真正生效时显示“IPv4 兼容”。“TUN 双栈与 DNS 已确认”继续只描述本机状态，不宣称节点远端 IPv6 或外网可达。

### 3.2 地址含义固定

| 地址/对象 | 行为 |
| --- | --- |
| Fake-IP | 首版固定 IPv4 池 `198.18.0.0/15`，不配置 IPv6 假地址池。其 A 为假地址、AAAA 为成功空回答，与真实出口是否允许 IPv6相互独立。 |
| 普通代理解析域名 | 客户端地址查询走 Fake-IP；核心还原域名后，仍经原 DNS 出口投影取得真实地址，再执行有序分流。 |
| 明确直连解析域名、默认直连域名 | 沿用物理网络真实解析，减少国内/内网兼容变化；纯 IP 规则仍不在 DNS 阶段决定出口。Fake-IP 的分配不代表最终必走代理。 |
| 本地名字 | `localhost` 及其子域、单标签主机名、`.local`、反向解析等走固定本地解析例外，保留系统更具体解析器与搜索域行为。普通私有完整域名遵守现有域名分流，不猜测企业域名。 |
| 真实目标 | 默认允许 IPv4/IPv6；兼容模式的业务 `resolve` 只允许 IPv4，并限制公共业务 AAAA 回答。例外后的真实 IPv6 字面流量被核心明确拒绝。 |
| 本机/局域网 IP | 既有保护直连优先于公共 IPv6 拒绝，包括 IPv6。经应用解析但不在本地名字例外中的仅 AAAA 私有域名，兼容模式下仍可能不可达。 |
| 节点服务器域名/IP | 保持独立物理网络引导解析；不继承业务 IPv4 限制，不转换 IPv6 字面地址，不承诺修复节点入口不可达。 |
| 系统网络 | 保留 TUN 双栈地址、IPv4/IPv6 路由覆盖与就绪判断；不删除 IPv6 路由来规避故障，不修改网卡 IPv6 或持久 DNS 偏好。 |

Fake-IP 池是保留用途，不能同时用作真实目标网段；不增加自动换池或用户自定义池。业务 IP 策略必须发生在还原/真实解析之后，不能因为宽网段规则覆盖该地址池就误判。现有具体规则或物理网络确实使用该池时，要在连接准备阶段给出可定位的冲突错误，保留设置；不能使整个设置文件被判损坏或要求初始化。仅因宽网段包含该池不拒绝有效规则。

### 3.3 明确不做

不增加自定义核心、Go 嵌入、节点能力测速/探测、逐节点覆盖、自动切换地址族、崩溃重连、系统代理、通用 DNS 编辑器、配置插件或通用资源事务框架。壳不实现 DNS、Fake-IP 映射、流量匹配、TLS 失败重试或 IPv6→IPv4 地址转换。不新增生产依赖。

## 4. 目标代码边界

```text
设置/节点操作
  → SessionService 冻结 ConnectionInput
  → 已认证的短期 worker
      → 准备官方核心与固定规则材料
      → 派生运行绑定：规则文件、用户映射缓存、可选活动接口
      → 单一编译入口 → 核心 check
      → 旧核心退出并关闭缓存 → 新核心启动 → 确认 TUN/DNS
  → 发布实际运行状态 → 保存成功恢复输入

业务请求：系统 DNS → Fake-IP 或真实直连回答 → TUN
  → 核心还原域名 → DNS/本地保护 → 真实地址解析
  → 本地保护 → 有序策略/默认出口 → 真实拨号
```

### 4.1 冻结输入归业务模型

把 `session/tunnel.rs` 的 Connection 移到 `profile/connection.rs`，命名为 `ConnectionInput`；继续只有闭合 Node、Routing、固定来源版本、官方核心版本，增加 `ConnectionOptions { ipv4_compatibility: bool }`。不带缓存路径、控制端口、secret 或自定义 JSON。

保留一套节点选择/规则版本/设置快照到 ConnectionInput 的构造入口，供期望状态、手动连接、换节点和应用使用；恢复直接使用已保存输入。保留原“切换固定当前核心、停止后首次启动才可采用更新核心”的规则。

有效指纹在原节点参数、有效规则与规则版本基础上加入连接选项，继续排除名称、标签、禁用规则内容、随机端口和缓存路径；不把已准备的新核心当成待应用分流变更。校验复用既有 NodeSpec / Routing / Version，不重建整个节点库来验证单连接。

### 4.2 配置只在一个地方组装

`profile/config.rs` 保留唯一编译入口，输入为 ConnectionInput 与内部运行绑定；拆成 DNS、路由、出口和 experimental 几个普通函数即可。保持 JSON 库，不创建通用配置 AST、策略引擎、builder 框架或多后端插件接口。

规则内容下载/核验/落地在调用方准备完成后，将固定版本对应的路径传给编译器；编译器不下载、不创建运行目录、不启停核心。GUI 普通权限检查与 worker 正式运行复用语义编译，分别派生自己的检查/运行路径。

`cache_file` 与可选 `clash_api` 在这里一次生成。删除 worker 和相应测试中整块覆盖 experimental 的做法；没有活动能力仍保留 Fake-IP 缓存，活动不可用不能导致连接策略变化。

不保留一套旧生成器作为静默回退。配置检查失败沿用候选失败处理，原始配置走现有独立入口。

## 5. DNS 与路由具体设计

### 5.1 分开客户端回答与核心真实解析

保留 local 与 proxy-dns 两条真实解析路径，固定配置一个 fakeip server。即使当前改成默认直连、没有代理域名，也保留 server 与缓存以识别旧映射。不能把 `dns.final` 简单指向 Fake-IP，或让核心 `resolve` 再取到假地址。

基于同一份有序域名投影生成规则：

1. 固定本地名字例外先交给 local；不把所有“直连 IP 段”投影成 DNS 域名规则。
2. IPv4 兼容时，对其余业务 AAAA 查询返回成功空回答，不影响独立的节点引导解析。
3. 每个代理域名条件先生成 A/AAAA→fakeip，再生成相同条件→proxy-dns；直连域名条件只生成→local。查询类型与域名条件显式 AND，多域名内部仍显式 OR，保持原投影顺序，不把原逻辑组改成隐式多条件匹配。
4. 默认代理时，末尾增加 A/AAAA→fakeip，DNS final 保持 proxy-dns；默认直连时 final 保持 local。
5. 使用官方 1.14.4 内部 Lookup 不允许 Fake-IP、会跳过 fakeip 路由的行为，让业务 `resolve` 继续落到真实解析规则；必须先用真实核心验证这一编译方案，不能只依据字段名推断。

不使用 `inbound: tun-in` 单独区分两类查询：内部解析仍可能继承同一个 inbound。真实解析服务器选择仍只看域名投影，IP 规则在解析后才能改变实际出口，与现有合同一致。

TXT/PTR 等查询保持真实解析。HTTPS/SVCB 地址提示、应用独立 DoH/DoT 和旧真实地址缓存可能绕开 Fake-IP 分配，仍是实际 IP 请求；不默认为修复故障而全面屏蔽 HTTPS/SVCB、关闭 ECH 或 QUIC。把这些路径纳入浏览器测试，不能把 Fake-IP 宣称为全部流量必经机制。

### 5.2 核心还原后再匹配与拨号

官方核心在进入规则前恢复 Fake-IP 对应域名；保留现有 sniff、DNS 劫持及解析前后本地保护。用户策略前必须保留真实 `resolve`：关闭兼容时按现有双栈策略，开启时明确 `ipv4_only`。

公共 IPv6 字面请求在 DNS 劫持和本地 IP 保护之后、业务出口之前明确拒绝，使用核心 `no_drop` 语义避免高频时变成静默丢包。兼容模式不靠 TCP 建连成功后的自动重试，也不把 v6-only 站点默默转成直连。

核对真实解析结果进入实际拨号：官方 `route/conn.go` 会消费 DestinationAddresses；有专用 ConnectionHandler 的协议需另外核对。必须通过受控出口记录证明确实请求了 IPv4，不能只检查客户端拿到 IPv4 假地址。不得仅修改代理 outbound 的 `domain_resolver`，该字段处理的是节点服务器域名。

## 6. 映射缓存属于持久运行资源

### 6.1 路径、身份与权限

增加一个局部缓存路径/生命周期模块，例如 `session/tunnel/cache.rs`，复用受保护根目录、私有文件工具和机器级租约，不另建后台进程或缓存服务。

机器级根目录继续保存官方核心与运行残留；映射使用 `<protected-root>/state/<owner-key>/fakeip-v1/cache.db`。owner-key 从已认证控制端的 OS 用户身份派生：Unix UID/审计身份，Windows 进程 token SID；相关读取集中在现有 platform 授权实现。先核对对等端，再派生 key；不能信任 IPC 字符串、前端路径或 helper 提权后自身的 root/管理员身份。

授权 worker 返回/持有 Channel 与已验证的用户上下文，仅在内部传递缓存绑定。继续核对同构建/同安装身份；闭合连接消息改变后一次升级现有握手协议，不增加旧协议兼容分支，不扩大管理员命令面。

目录仍是受保护私有目录，校验固定路径和链接边界；普通 GUI 无权读写映射数据库。核心的 cache_file 只开启 `store_fakeip`，不开启历史 DNS 回答持久化；映射可能含访问域名，需要在数据说明中明确本机持久保存。WebView 不取得缓存内容、路径或控制 secret。

cache_id 与假地址布局稳定，不包含节点 ID、规则修订、会话 ID或核心补丁版本。切节点不换地址池，不为每次连接创建一个数据库。

### 6.2 与候选替换的顺序

| 阶段 | 缓存与旧连接约束 |
| --- | --- |
| 准备候选 | 生成配置、核验规则、执行官方 `check`；不启动候选核心，不取得在用缓存的写锁，不删除或复制在用数据库。 |
| 候选检查失败 | 删除候选临时目录，旧 PID、映射与转发继续运行。 |
| 正式替换 | 先停止旧核心并确认真实退出、释放缓存，再启动新核心打开同一数据库。机器级租约继续只允许一个所有者。 |
| 新连接失败 | 完成资源清理后，最多恢复一次旧固定输入，继续打开同一地址池/数据库；不回滚或复制数据库快照。映射与节点无关。 |
| 断开/退出/失联 | 停止核心、关闭数据库，释放 TUN/DNS/helper，删除临时配置；保留映射文件供下次显式连接。 |
| 核心/worker 被强杀 | 沿用现有受保护进程记录恢复；确认残留退出后才允许重新打开数据库，不做崩溃自动重连。不能保证被强杀前尚未落盘的最后一批映射。 |

官方 check 只构造/关闭实例，数据库在服务 Start 阶段打开；仍须用实际核心做“旧进程持锁时检查候选”的回归，防止将来升级改变假设。GUI 检查使用自身隔离的临时绑定，不能触碰管理员数据库。

固定池与核心管理的映射复用控制记录数量；不新增壳侧映射数据库、定时压缩或定时删库。磁盘增长、池回绕和正常重连一致性进入长跑测试。不得以清理缓存作为每次启动成功的条件。

官方核心对部分损坏缓存会重建数据库，这可能使浏览器旧地址失效，甚至与新分配地址不再对应；损坏、外部删除后的旧地址不纳入透明恢复保证，需要重新解析，必要时重启浏览器。壳不解析/修复数据库、不根据假地址猜域名、不在失败时偷偷切回真实 IP。缓存缺失、不可写、被占用及核心重建的实际行为在第一阶段明确记录。正常准备、重连或恢复也会丢失/错配映射时，暂停 Fake-IP 默认上线，不临时加入第二套缓存实现。

## 7. 设置、恢复与界面贯通

- Profile 保存 ConnectionOptions；ConnectionInput 保存同一选项的冻结副本。字段缺省为关闭，现有 schema 5 与历史成功快照可按默认值读取，不要求重新导入节点。
- 增加专用 `connectionRevision`，默认 0，写事务只修改连接选项与自身修订。避免与节点名称、分流草稿或下载镜像共用修订；不建立通用设置域框架。
- 类型化 IPC 只接受 ConnectionOptions 与 expectedRevision，由现有 Profile 操作门禁接纳；不接受配置 JSON、核心路径、缓存路径或 server URL。
- 同步公开 Settings、轻量 session revisions、TS DTO、前端刷新检测与 UI 夹具。不能只把新字段加到设置文件，漏掉每秒轻量刷新。
- worker 公开实际 `runningConnectionOptions`，由其实际输入产生；SessionService 的 applied、成功恢复快照与摘要保持一致。候选恢复旧连接后，不能显示新模式已生效。
- 一次恢复读取最后成功输入，不读页面草稿；保存待应用选项不篡改成功快照。主动停止、清理失败和 macOS 交互授权限制遵守现有约定。
- 设置区复用现有表单/状态文案和样式；一个小控制器接入 dirty、documentId/requestId 退出预检、保存/放弃/取消。收起保留草稿，后台刷新不覆盖输入。
- Fake-IP 作为新版本节点编译行为在下次连接生效，不持久保存旧 DNS 后端，也不引入真实 IP/Fake-IP 两套运行分支。老浏览器的真实地址缓存可能需要重新解析；旧程序因未知新增字段拒读时保留原件，不能承诺新旧应用双向兼容。

## 8. 活动展示与错误归因

Fake-IP 由核心还原后的 host 仍是目标首选。活动采集继续相信核心 policy tag，不在 Rust/TS 重新执行规则。

官方 v1.14.4 的 Clash API 可能只有域名而没有实际选中的拨号 IP。此时不新增“真实出口 IPv4/IPv6”推测字段；未知就不显示。验收中的真实地址由受控服务器观察，不能从 Fake-IP 或待尝试地址列表反推。仅在真实数据格式需要时调整 target 格式化，保留未知原描述与大小限制。

兼容模式的拒绝属于连接行为，不能从活动采样缺失推断；按需查看核心日志。采集不可用不停止网络，缓存不可用也不能被活动接口“可选”逻辑吞掉。

## 10. 分阶段实施

同一主题按以下顺序推进；每阶段只提交该阶段必要内容，不让未通过的实验成为隐藏生产选项。

1. **验证官方核心能力与边界。** 在隔离目录和回环入口，用 1.14.4 证明 Fake-IP→域名→真实解析→预期 IP 拨号、内部 Lookup 跳过 fakeip、AAAA 空回答、候选 check 不锁库、重连持久映射和损坏缓存行为。审计六种受支持协议的拨号路径，记录专用 handler。失败时先修订方案；不先发布 UI。
2. **整理输入与编译边界。** 移动 ConnectionInput，统一构造与指纹，分离材料/运行绑定，统一 experimental 组装；保持既有行为的真实核心回归，删掉 worker/test 的块覆盖。此阶段不引入通用抽象或双生成器。
3. **落地 Fake-IP 与持久资源。** 接入认证用户缓存、生产 DNS 投影及路由，迁移测试真实地址；验证准备、切换、恢复、停止与退出。Fake-IP 默认切换只在整条链路可验收后启用。
4. **贯通 IPv4 兼容与公开状态。** 原子设置、独立修订、闭合 IPC、worker/恢复输入、实际摘要及一个设置入口一起完成。已有流程全部接同一构造入口。
5. **原生与发行验收。** 五目标原生运行器、真实安装包、Mac/Windows 浏览器和故障节点对照。更新正式功能/架构/使用/开发文档，删除本计划，不另建完成归档。

## 11. 验收矩阵

| 项目 | 必须证明的结果 |
| --- | --- |
| DNS 与还原 | 生产编译的代理域名 A 为池内地址、AAAA 成功空回答；连接该地址恢复正确域名；未对客户端查询做 Fake-IP 的测试不能替代此项。 |
| 真实出口族 | 双栈与 IPv4 兼容分别验证，出口服务器记录真实目的地址。包含 IPv4 HTTPS 成功、IPv6 TCP 可建立但 TLS 失败的夹具，兼容开启后成功；不能只用 TCP echo。 |
| 分流顺序 | 早 IP/晚域名、早域名/晚 IP、混合 OR、固定站点、默认直连/代理、禁用和重排全部保持核心首次匹配；私网解析结果仍保护直连。 |
| 引导解析 | IPv6 字面节点与仅 AAAA 节点入口保持独立；业务 IPv4 兼容不使入口解析变成仅 IPv4；本地 DNS 无回入自身 TUN 的循环。 |
| 兼容边界 | 私有完整域名、单标签、`.local`、hosts、反向查询、HTTPS/SVCB 地址提示、浏览器独立 DoH/DoT、旧真实 IP 缓存、IPv6 字面目标和仅 IPv6 网站逐项记录；不靠关闭 QUIC/ECH 让测试通过。 |
| 持久映射 | 保持旧 Fake-IP 不重新查 DNS，在应用重连、换节点、应用规则及失败恢复后仍访问原域名；重复正常启停不因删除随机目录丢映射。池回绕与文件增长单独长跑。 |
| 资源与权限 | 候选检查时旧核心持锁不受影响；正式切换无双写者；取消/停止/退出/失联/强杀清理遵守原合同；不同认证用户隔离，拒绝任意路径及链接，错误不静默降级。 |
| 状态与持久化 | 保存不换 PID；应用后才更新实际模式；失败恢复旧输入；期望/实际/成功快照一致；修订冲突不丢草稿；节点改名、下载偏好与规则草稿互不覆盖；历史 schema 5 可读。 |
| 活动与隐私 | 目标优先域名、规则来源可信、未知实际地址不编造；活动能力关闭时缓存仍生效；凭据、控制 secret、映射内容不回传。 |
| 原始配置 | 配置原件和外部核心字节不变，不注入 Fake-IP、缓存或监控，模式切换仍须先停止。 |

沿用 `src-tauri/tests/profile.rs` 的官方核心入口，但改为只替换上游传输、回环入口和出口观察，不覆盖生产 DNS 规则、Fake-IP server 或 experimental。真实测试目标改用独立于 Fake-IP 的受控地址，例如经路由验证的 `203.0.113.0/24`；测试数据中显式区分虚拟地址和真实地址，避免全局字符串替换。

网络脚本保留现有双栈 TCP/UDP 与清理验收，增加系统 getaddrinfo→Fake-IP→真实业务请求。可控 DNS/HTTPS 夹具留在测试构建/脚本，允许在夹具构建注入受限本地上游，不给生产 IPC 增加自定义 DNS、配置或管理员能力。先覆盖现有 Shadowsocks 基线及实际故障节点使用的协议；有专用拨号 handler 的协议补对应集成，不把一种协议通过写成全部通过。

自动测试不把 Gmail 固定 HTTP 200 当作唯一依据；Gmail、Google 登录等作为 Mac/Windows 人工浏览器冒烟，并用另一节点对照。测试记录核心版本、节点协议、解析路径、兼容开关、实际目标族及残留清理，区分客户端问题和远端网络问题。

代码实现时执行相关 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run build`，并显式运行被忽略的真实核心项。最终发行对 Windows x64/ARM64、Linux x64/ARM64、macOS Apple Silicon 的实际包做原生验证，ARM64 不用交叉编译代替。发布记录分别写明授权交互、真实节点、签名及未覆盖协议/物理切网范围。

## 12. 交付、风险与退出条件

正式行为落入 `docs/features/routing.md`、`core.md`、`activity.md`、`docs/usage.md`、`architecture.md`、`development.md`；导航只维护 `docs/README.md`。实现前不把计划写成已支持能力。应用版本仍只在 `src-tauri/tauri.conf.json` 修改。

必须单独说明三项风险：旧真实 DNS/旧 Fake-IP 缓存不保证立刻失效；缓存丢失/损坏/池复用不保证透明恢复；未经过应用 DNS 的请求不能保证获得域名。仅 IPv6 公网服务在 IPv4 兼容开启时不可用。缓存记录是本机敏感材料，不能附带上传到诊断或发行证据。

若第一阶段发现官方核心无法同时保证真实 IP 有序分流、正确真实地址拨号和正常重连映射，本主题停止默认 Fake-IP 上线，保留证据并收敛设计；不通过替换为自定义核心、复制协议逻辑或增加多套回退后端来完成验收。若仅远端节点依然 IPv6 不通，使用明确 IPv4 兼容或更换节点，不归因于 Fake-IP 失效。
